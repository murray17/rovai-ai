## 角色路由

- 收到文档版复核邀请：作为固定搭档，只返回独立建议，不修改文档；
- 用户启动或回答，或收到本次固定搭档对当前文档版复核邀请的回复：作为邀请者继续完整文档版会话。

每个决策点使用一条新的复核邀请。固定搭档直接回复该邀请；旧邀请的迟到建议只作为补充。

Agent 不能选择任意 reply target。邀请者从当前用户/续跑消息触发的 Run 发请求；搭档从该邀请触发的 Run 返回时，Core 自动建立对邀请的直接回复关系。

## 会话边界

- 持续追问，直到与用户达成共同理解；
- 沿决策树逐项解决问题，先处理会影响后续问题的上游决定；
- 同一场会话一次只推进一个尚未解决的决策点；
- 一次只问一个问题，并等待用户回答后再继续；
- 每题都给出推荐答案，不只罗列选项；
- 能从代码、权威文档、当前 AgentRun 已投递上下文或 Camp 公共历史取得的事实，自己查，不问用户；
- 把真正需要取舍的决定交给用户；
- 在用户明确确认已经达成共同理解前，不开始产品实现。

## 固定搭档

会话开始时，从当前 Camp 中选择一位不是自己的、仍在场且可以接收协作请求的队员作为固定搭档。

优先选择与当前问题专业最匹配的队员。整场使用同一位搭档；只有用户要求、搭档不可用或问题明显跨入另一专业领域时才更换，并说明原因。

如果没有合格搭档，明确说明已降级为单人追问，然后继续相同的逐题与文档协议。不要虚构第二个观点。

## 邀请者：发起复核

先整理当前唯一决策点，再通过 `rovai send --to <固定搭档 Agent ID> --body <邀请正文>` 向固定搭档发送一次显式公共 A2A 请求；不要使用 `--to-user`。需要确认参数时运行：

```text
rovai send --help
```

使用 Core 提供的准确 Agent ID 寻址，不猜测 ID。不要附带自己的推荐。

```markdown
### 双人追问与文档 · 复核邀请

**用户目标**

> <用户原始目标>

**当前决策点**

> <本轮唯一需要解决的问题>

**已经确认**

- <事实、术语或此前决定；没有时写“暂无”>

**候选选项与约束**

- <选项>
- <可逆性和文档影响>

请只提供独立复核建议，不修改项目文档。
领域词汇与 ADR 维护由邀请者负责。

请直接回复这条复核邀请，并给出：

1. 容易理解的问题解释；
2. 各选项的利弊与可逆性；
3. 你的独立建议；
4. 用户可以直接采用的一句话答案。
```

同一决策点已经发出邀请时，不重复发送。发送成功只证明公共消息和 Message Delivery 已建立，不证明搭档已经开始或完成。

发送后结束本次响应，等待搭档回复；不要 sleep、轮询或伪造意见。

## 固定搭档：返回建议

只在当前 AgentRun 由文档版复核邀请触发时返回建议。使用 Runtime 提供的可信邀请者 Agent ID 作为唯一收件人。

不要读取领域建模、词汇表或 ADR 参考，不修改 `CONTEXT.md`、ADR 或其他项目文件。

```markdown
### 双人追问与文档 · 搭档建议

**当前决策点**

> <原样保留或准确重述本轮问题>

**问题解释**

<简明解释>

**选项与可逆性**

- <选项 A>
- <选项 B>

**独立建议**

<建议与主要依据>

**用户可以直接采用的一句话**

> <一句话答案>
```

通过 `rovai send --to <邀请者 Agent ID> --body <建议正文>` 从当前邀请触发的 Run 返回；不要使用 `--to-user`。Core 会自动让建议直接回复这条邀请。不要替用户决定、开始实施、继续委派或一次提出多个问题。命令 accepted 后结束本次响应。

## 邀请者：收到建议

只把以下消息作为当前决策点的正式结果：

- Runtime 可信发送者是当前固定搭档；
- 当前触发消息的直接父消息是当前文档版复核邀请；
- 内容确实回答当前决策点。

其他成员的公开意见可以阅读，但不能代替固定搭档、完成往返或推进决策点。

收到正式建议后，不再重复邀请。结合搭档意见与自己的判断，向用户给出简明解释、关键取舍与可逆性、明确推荐，以及恰好一个需要用户回答的问题。意见不一致时诚实说明分歧和依据。

用户回答后记录决定，再进入下一个受影响的决策点，并按顶层 Skill 的文档职责处理已经形成的稳定术语与符合准入的 ADR。

新的决策点使用新的复核邀请。旧邀请的迟到建议只作为补充，不自动退回；会话结束后也不自动重开。

## 重试

只有请求明确失败、搭档明确不可用或回复无法读取时才重试。重试时创建新的复核邀请。

旧邀请之后到达的回复只作为补充，不满足新邀请。

## 完成

决策树没有未解决分支时，总结目标、已确认决定、约束、风险、文档变更和开放决定，然后只问一次用户是否确认已经达成共同理解。

得到明确确认后结束追问；后续实施仍须遵守当前授权和仓库规则。
