# 双人追问与文档

邀请者负责持续追问和文档维护，一位固定搭档负责独立复核。固定搭档只提供建议，不修改项目文档。

## 角色与轮次关联

- 用户启动会话或回答当前开放轮次：作为邀请者继续。
- 当前 AgentRun 由文档版双人追问复核请求直接触发：作为固定搭档，只处理这条请求。
- 当前输入是固定搭档对本轮有效复核邀请的直接回复：作为邀请者继续。

始终以 Runtime 提供的可信发送者、当前 AgentRun 的触发消息和直接回复关系判断角色；消息标题只帮助阅读。

邀请者只把当前固定搭档对本轮当前有效邀请的直接回复作为正式建议。普通版建议、旧轮、已失效邀请或迟到建议只作补充，不能推进、回退或重开会话。

邀请者按需读取：

- [领域建模纪律](references/domain-modeling.md)
- [词汇表格式](references/context-format.md)
- [ADR 判断与通用格式](references/adr-format.md)

固定搭档不读取这些文档规则。

## 基本流程

1. 选择一位合格的固定搭档。
2. 每轮选择前提已经确认、彼此不依赖的 1–4 个问题。
3. 把本轮问题一次发给搭档，不附带自己的推荐。
4. 搭档用一条消息逐题返回建议、理由和风险。
5. 邀请者结合双方判断，一次向用户提出本轮全部问题，每题给出推荐。
6. 用户回答后，只关闭明确回答、取消或已经失效的问题；当前轮仍开放时继续该轮。
7. 及时维护用户已经确认的术语和达到准入门槛的架构决定。
8. 当前轮全部关闭后，才整理下一轮问题。
9. 没有重要问题后，请用户确认共同理解；确认前不开始产品实现。

依赖本轮其它答案的问题留到下一轮。能从代码、权威文档、工具、当前 AgentRun 已投递上下文或 Camp 公共历史查明的事实，不问用户。

## 固定搭档

固定搭档必须不是自己、仍在当前 Camp、能够接收协作请求。使用 Runtime 或 Core 提供的可信 Agent ID 寻址，不根据显示名或正文猜测 ID。

优先选择与当前问题最匹配的队员，整场使用同一位搭档。只有用户要求、搭档离场或不能接收请求，或者问题明显进入原搭档无法有效判断的专业领域时才更换，并向用户说明原因。

没有合格搭档时，说明降级为单人追问，并继续相同的分轮、开放轮次和文档规则；不要虚构第二个观点。

## 开放轮次

一轮在其中所有问题被明确回答、取消或失效前保持开放。为本轮问题使用稳定编号 `Q1`–`Q4`。

- 未回答问题保留原编号、原问题和已有搭档建议；内容未变时不重复复核。
- 开放轮次期间不混入新问题；新问题等当前轮全部关闭后再处理。
- 用户改变某题的问题、选项或约束时，保留编号，只重新复核该题。
- 重新复核后，只接受固定搭档对更新后邀请的直接回复；更早建议只作补充。
- 用户只回答部分问题时，只维护已经确认部分的文档，并继续列出仍开放的原编号和已有建议。

## 消息方式

- 邀请者请求搭档复核：`rovai send --to <搭档 Agent ID> --body <本轮问题>`
- 搭档返回建议：`rovai send --to <邀请者 Agent ID> --body <本轮建议>`
- 邀请者向用户提出问题或请求最终确认：`rovai send --to-user --body <正文>`

使用可信 Agent ID。消息返回 `accepted` 后才结束当前响应；`accepted` 只证明消息和 Delivery 已建立，不证明接收方已经开始或完成。发送异常时遵循 CLI 返回的 recovery 指示，不盲目重发，也不轮询或代写下一方结果。

## 本轮内容

复核请求一次列出用户目标、已经确认的内容，以及每个 `Q1`–`Q4` 的问题、主要选项、重要约束和可能影响的文档。某题失效后的新请求只包含该题的更新内容。

搭档只处理触发当前 AgentRun 的请求，不继续委派、不增加问题，也不修改 `CONTEXT.md`、ADR 或其它项目文件；按原编号逐题给出建议、最主要理由和风险。

邀请者一次向用户提出本轮全部开放问题。每题说明主要取舍、自己的推荐、搭档看法以及确认后可能影响的文档；双方意见不同时准确说明分歧，并请用户按原编号分别回答。

## 维护文档

- 只记录用户明确确认的术语和决定；未回答、含糊或仅由搭档建议的内容不得写成已确认事实。
- 稳定领域术语及时写入适用的 `CONTEXT.md`；与现有词汇冲突时先问清楚。
- 只有难以改变、缺少背景会令人意外且存在真实取舍的决定才记录 ADR。
- 写入前读取仓库的文档导航、`AGENTS.md` 和相关维护规则；仓库规则决定文件位置、格式、编号和校验命令。
- 文档校验失败时只修复相关文档，不开始尚未获准的产品实现。

## 完成

没有重要问题后，总结已确认决定、关键约束和风险、新增或修改的领域词汇与 ADR，以及仍未确认但不阻塞的事项，并按“消息方式”请求用户确认共同理解。用户明确确认后结束会话；旧轮或迟到建议不能重开会话。
