# Implementation Workflow

Use after the project design brief is confirmed.

## Before Coding

Confirm:

- project understanding checkpoint completed
- reference/taste route checkpoint completed
- design brief checkpoint completed
- delivery format selected
- files and framework understood

## Implementation Rules

- Follow the confirmed `PROJECT_DESIGN.md` or `design.md`.
- Use the existing stack, routing, components, tokens, and naming conventions.
- Preserve real content and product terminology.
- Add new abstractions only when they match the project or reduce real complexity.
- Cover expected states: hover, focus, active, selected, disabled, empty, loading, error.
- Keep responsive behavior explicit.
- Do not add filler sections, fake data, decorative cards, or speculative product features.
- If implementation reveals the brief is wrong, stop and ask to revise the brief.

## Visual Craft During Coding

Check spacing, alignment, type scale, contrast, border radius, shadows, and component state consistency as you implement.
Do not leave chart labels, buttons, or text overlapping.
