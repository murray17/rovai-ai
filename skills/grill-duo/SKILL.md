# 双人追问

一个负责问到底，一个负责把选项掰开讲明白。让用户只承担真正的取舍，不承担事实搜索或术语翻译。

## 先判断当前角色

- 用户启动会话或回答上一题：作为邀请者继续；
- 收到另一位成员发来的复核邀请：作为固定搭档独立复核；
- 收到本次固定搭档对当前复核邀请的回复：作为邀请者恢复会话。

公开消息使用：

```text
### 双人追问 · 复核邀请
### 双人追问 · 搭档建议
```

每个决策点使用一条新的复核邀请。搭档建议直接回复该邀请。

自然标题是 Skill 发现与阅读线索，标题只提示阶段，不证明身份、当前决策点或回复关系。进入 Skill 后，以 Runtime 提供的可信发送者和当前触发消息的直接回复关系确认角色；标题被改写或省略但正文语义和这些事实清楚时仍可继续。

## 会话边界

- 持续追问，直到与用户达成共同理解；
- 沿决策树逐项解决问题，先处理会影响后续问题的上游决定；
- 同一场双人追问一次只推进一个尚未解决的决策点；
- 一次只问一个问题，并等待用户回答后再继续；
- 每题都给出推荐答案，不只罗列选项；
- 能从代码、权威文档、当前 AgentRun 已投递上下文或 Camp 公共历史取得的事实，自己查，不问用户；
- 把真正需要取舍的决定交给用户；
- 在用户明确确认已经达成共同理解前，不开始实施。

## 固定搭档

会话开始时，从当前 Camp 中选择一位不是自己的、仍在场且可以接收协作请求的队员作为固定搭档。

优先选择与当前问题专业最匹配的队员；能够自行取得选择依据时，不要求用户选人。

整场会话使用同一位搭档。只有以下情况才更换，并向用户说明原因：

- 用户明确要求更换；
- 搭档已经不在场或不能接收请求；
- 问题明显进入另一专业领域，原搭档无法提供有效判断。

如果当前 Camp 没有合格搭档，明确说明已降级为单人追问，然后继续相同的逐题协议。不要虚构第二个观点。

## 邀请者：发起复核

先整理当前唯一决策点，再通过 `rovai send --to <固定搭档 Agent ID> --body <邀请正文>` 向固定搭档发出一次显式公共 A2A 请求；不要使用 `--to-user`。需要确认参数时运行：

```text
rovai send --help
```

使用 Core 提供的准确 Agent ID 寻址，不猜测 ID。不要附带自己的推荐，避免锚定搭档。

```markdown
### 双人追问 · 复核邀请

**用户目标**

> <用户原始目标>

**当前决策点**

> <本轮唯一需要解决的问题>

**已经确认**

- <事实或此前决定；没有时写“暂无”>

**候选选项与约束**

- <选项 A>
- <选项 B>
- <可逆性、成本或约束>

请独立给出：

1. 容易理解的问题解释；
2. 各选项的利弊与可逆性；
3. 你的独立建议；
4. 用户可以直接采用的一句话答案。

请直接回复这条复核邀请，不要替用户决定、开始实施或继续委派。
```

同一决策点已经发出邀请时，不重复发送。

发送成功不代表搭档已经完成。发送后结束本次响应，等待搭档回复；不要 sleep、轮询或代写搭档意见。

## 固定搭档：返回建议

只在当前 AgentRun 由复核邀请触发时返回建议。使用 Runtime 提供的可信邀请者 Agent ID 作为唯一收件人，不要把复核转交给其它成员。

独立判断，不沿用邀请者未提供的推荐。

```markdown
### 双人追问 · 搭档建议

**当前决策点**

> <原样保留或准确重述本轮问题>

**问题解释**

<简明解释>

**选项与可逆性**

- <选项 A>
- <选项 B>

**独立建议**

<建议与主要依据>

**用户可以直接采用的一句话**

> <一句话答案>
```

通过 `rovai send --to <邀请者 Agent ID> --body <建议正文>` 从当前邀请触发的 Run 返回；不要使用 `--to-user`。Core 会自动让建议直接回复这条邀请。不要替用户决定、开始实施、继续委派或一次提出多个问题。命令 accepted 后结束本次响应。

## 邀请者：收到建议

只把以下消息作为本轮正式复核结果：

- Runtime 可信发送者是当前会话选定的固定搭档；
- 当前触发消息的直接父消息是当前决策点的复核邀请；
- 内容确实是在回答该决策点。

其他成员的公开意见可以阅读，但不能代替固定搭档、完成本轮往返或推进当前决策点。

收到正式建议后，不再为同一复核邀请重复发送请求。结合搭档意见与自己的判断，向用户输出：

- 一段简明的问题解释；
- 关键取舍与可逆性；
- 明确的推荐答案；
- 恰好一个需要用户回答的问题。

如果自己的推荐与搭档不同，诚实说明分歧和依据，不强行合并成虚假共识。

用户回答后记录已经确认的决定，再进入下一个仍受影响的决策点。新的决策点使用新的复核邀请。

旧邀请的迟到回复只作为补充，不自动退回旧问题；会话已经结束时，迟到建议也不自动重开追问。

## 重试

只有复核请求明确发送失败、搭档明确不可用或回复无法读取时才重试。重试时创建一条新的复核邀请。

旧邀请之后到达的建议只作为补充，不满足新的复核邀请。

## 完成

当决策树没有未解决分支时，简要总结目标、已确认决定、约束和仍然存在的风险，然后只问一次用户是否确认已经达成共同理解。

得到明确确认后结束追问会话；后续实施仍须遵守当前任务授权和仓库规则。
