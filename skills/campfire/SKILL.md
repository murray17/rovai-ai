# 篝火讨论

Campfire 是由 Default Lead 主持的多人讨论流程。成员先独立形成判断；只有存在会改变结论的关键分歧时，才进行一轮定向回应；最后由主持人发布一份统一纪要。

## 使用边界

使用 Campfire：

- 用户要求“大家讨论一下”“让几个人一起看看”或“从多个视角分析”；
- 用户要求正反讨论、挑战一个方案、比较多个选择，或讨论后给出建议；
- 普通成员收到 Default Lead 发出的独立观点请求或定向回应请求；
- Default Lead 收到符合条件的转交请求；
- Gather 完成后，原发起者需要继续判断、回应或收口。

不使用 Campfire：

- 问题明确且只需一人查询、执行或完成普通 review；
- 用户只希望两人持续追问需求，而不是多人独立判断；
- 当前 Camp 找不到至少两位可参与成员；
- 用户要求严格隔离的技术盲评。CampMessage 是公开的，Campfire 只能要求成员独立作答，不能保证信息隔离。

参与成员不足两位时，说明改为单人分析或结束，不虚构第二种声音。

## 角色与触发路由

执行任何动作前，先判断当前角色和当前触发。

| 当前角色 | 当前触发 | 唯一允许的动作 |
|---|---|---|
| 当前 Default Lead | 用户直接要求多人讨论 | 读取 `references/lead.md`，进入第一轮 |
| 当前 Default Lead | 明确的《篝火讨论 · 转交请求》 | 读取 `references/lead.md`，核对后进入第一轮 |
| 普通成员 | 用户广播、`@所有队员`，或用户同时触达 Default Lead | 不发表观点，不调用 A2A，结束当前 Run |
| 普通成员 | 用户只触达当前成员，并明确要求召集多人讨论 | 读取 `references/member.md`，转交一次后结束 |
| 普通成员 | Default Lead 的独立观点请求 | 读取 `references/member.md`，提交一条完整独立观点 |
| 普通成员 | Default Lead 的定向回应请求 | 读取 `references/member.md`，提交一条完整回应 |
| Gather 原发起者 | 独立观点请求对应的 `gather_completed` | 读取 `references/lead.md`，总结或发起回应轮 |
| Gather 原发起者 | 定向回应请求对应的 `gather_completed` | 读取 `references/lead.md`，发布纪要 |
| 任意角色 | 《篝火纪要》、迟到意见、无关成员观点 | 不自动续跑 |

普通成员在用户广播阶段不发表问题观点，也不向主持人发送“请继续”或类似控制消息。若运行环境要求生成一条最终文本，只输出：

```text
等待 Default Lead 发起讨论。
```

## 公共协议

1. 新 Campfire 只能由用户直接请求当前 Default Lead，或由一条符合条件的转交请求触发。
2. 普通成员的观点、回传、迟到消息和其他 Agent 消息都不能触发一场新 Campfire。
3. 同一个 Camp 中，当前 Default Lead 一次只推进一场尚未结束的 Campfire。
4. 第一轮使用一次 Gather，邀请 2–3 位成员独立作答，默认 3 位。
5. 第二轮是可选的定向回应 Gather，只围绕一个关键分歧，邀请 1–2 位成员。
6. 每场最多两轮 Gather。第二轮完成后必须发布纪要，不再追加第三轮或独立澄清轮。
7. 每位成员对每个请求只提交一条完整结果，正文目标为 200–250 个中文字符且最多不超过 300 个中文字符，不发送进度消息。
8. Gather accepted 后，主持人立即结束当前 Run；不轮询、不发布等待状态、不重复邀请。
9. 《篝火纪要》是本场讨论的终止输出。迟到消息不会自动更新纪要或重新开始讨论。
10. 用户可以随时停止、替换话题、移除成员或要求立即总结；优先服从用户最新指令。

## 基本流程

```text
用户提出多人讨论
    ↓
Default Lead 选择 2–3 位互补成员
    ↓
第一轮 Gather：独立观点
    ↓
Gather 完成，只恢复原发起者一次
    ↓
至少两份有效观点？
    ├─ 否：发布部分纪要或终止说明
    └─ 是：是否存在会改变结论的关键分歧？
              ├─ 否：发布《篝火纪要》
              └─ 是：第二轮 Gather，围绕一个分歧定向回应
                           ↓
                     发布《篝火纪要》
```

不要为了展示“讨论感”强行制造反方。没有实质分歧时，直接收口并在纪要中说明未开启回应轮。

## 当前讨论与用户介入

同一 Camp 中，若已有由当前主持人发起且尚未发布《篝火纪要》或《篝火讨论 · 终止》的 Campfire，不再启动第二场。

用户明确替换话题时，先停止旧讨论，再按新话题开始。用户要求立即总结时，使用已经形成的有效观点发布部分纪要，并准确标记未完成成员；不要继续等待或补写缺失观点。

## 角色指南

- 负责启动、处理 Gather 完成结果或发布最终纪要时，读取 [Default Lead 指南](references/lead.md)。
- 收到独立观点请求、定向回应请求，或需要转交讨论时，读取 [参与者指南](references/member.md)。
- 准备终止输出时，读取 [篝火纪要写作指南](references/notes.md)。
