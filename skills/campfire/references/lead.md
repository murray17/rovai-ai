# Campfire Default Lead 指南

负责主持一场篝火讨论或处理受邀成员回传时读取本文件。

## 开始与交接

确认用户原始话题、是否需要最终建议、是否要求正反视角，以及是否点名成员。

选择 2–3 位互补成员，并使用成员列表提供的准确 Agent ID 寻址，不根据显示名猜测路由身份。

当前响应者不是 Default Lead 时，把用户原话、指定成员和期望结果转交给 Default Lead，随后结束当前回复；不要同时另开讨论。

启动前确认当前 Default Lead 没有主动推进另一场未结束的 Campfire。新话题明确替换旧话题时结束旧讨论，并在新邀请开头简短说明旧话题已经结束、现改为新话题；意图不明确时只做一次最小确认。

## 邀请独立开场

运行 `rovai send --help` 确认当前命令参数。默认用一条消息同时邀请所有成员。

```markdown
### 篝火讨论 · 邀请

**话题**

> <尽量保留用户原话>

**已确认的共同事实**

- <没有则写“暂无”>

请结合你在当前 Camp 中的职责、经验和你认为最重要的风险，先独立给出判断。
不要引用同场其他成员的结论。请回复：

- 核心判断
- 2–3 个主要依据
- 最担心的失败方式或限制条件
- 希望其他成员回应的一个问题
- 置信度
```

用户逐人指定视角时，在同一邀请中增加：

```markdown
**视角分配**

- Alice：架构与 Runtime 兼容性
- Bob：产品价值与迁移收益
- Carol：实施成本与发布风险

请只从分配给你的视角先独立表达。
```

只有每位成员确实需要不同上下文材料时才分别发送个性化邀请。不同消息仍然公开，不声称形成私密材料分发。

不要附带自己的推荐。发送后结束当前回复，等待真实回传；不要轮询或代写成员意见。

## 接收开场观点

只把自己邀请参加本次讨论的成员回复纳入正式观点。收到无关成员意见时可作为普通 Camp 消息阅读，但不要计入本次 Campfire。

对每位成员记录一句核心判断、重要条件和置信度。合并真正重复的共识，保留条件性支持与明确反对，并选出最可能改变最终结论的一个分岔点。

没有实质分岔时直接准备纪要。

## 安排定向回应

整场主动安排 0–2 次定向回应，一次只邀请一位成员。

```markdown
### 篝火讨论 · 定向回应

**话题**

> <当前话题>

**回应的分岔点**

<明确问题；只引用与分歧直接相关的一小段>

请说明你是维持、修正原判断，还是只在某些条件下支持。不需要重复完整开场观点。
```

收到这一位的真实回复后再决定是否需要第二次。第二次必须解决仍可能改变结论的问题，而不是为了平均发言。

## 主动短澄清

Campfire 主动发起的短澄清全场最多一次。多处含糊时，只选最可能改变共识、分歧或最终建议的一处。

```markdown
### 篝火讨论 · 澄清

**话题**

> <当前话题>

我准备把你的最终立场写成：

> <一句话>

准确吗？不准确时请给出一条最小修改。
```

不接受新方案或长篇补充。其他不确定内容直接写入纪要，不继续增加往返。用户之后的新追问不计入这项限制。

## 最终发布

读取 [篝火纪要](notes.md)，通过一条不带成员收件人的普通公开消息发布唯一最终纪要。不要再次唤醒参与者。

发布后把讨论视为结束。迟到回复可以作为补充信息阅读，但不自动更新纪要或重新主持；只有用户明确要求时才继续。

不要因发布纪要自动创建 Task、写入 Memory 或 ADR，也不要直接开始实施。
