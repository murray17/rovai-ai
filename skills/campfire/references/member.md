## 1. 用户广播阶段

当当前 Agent 不是 Default Lead，并且用户：

- 向全体成员广播；
- 使用 `@所有队员`；
- 同时触达 Default Lead；
- 同时点名多位成员；

不得：

- 提前发表问题观点；
- 向 Default Lead 发送“请继续”等控制消息；
- 邀请其他成员；
- 自行启动 Campfire。

直接结束当前 Run。若运行环境要求生成一条最终文本，只输出：

```text
等待 Default Lead 发起讨论。
```

## 2. 窄范围转交

只有同时满足以下条件时，才向 Default Lead 转交一次：

1. 当前消息来自用户；
2. 用户只触达当前这一位普通成员；
3. 用户明确要求召集多人讨论；
4. 用户没有同时触达 Default Lead。

从可信 Collaboration State 读取准确的 `defaultLeadAgentId`，使用：

```text
rovai send --to <defaultLeadAgentId> --body <转交正文>
```

转交正文：

```markdown
### 篝火讨论 · 转交请求

#### 用户话题

> <逐字保留用户原始话题>

#### 用户指定成员

- <没有则写“未指定”>

#### 期望输出

<讨论、比较、建议或决策>
```

accepted 后结束当前 Run，不同时发表自己的观点。

## 3. 回复正式请求

只在当前 AgentRun 由以下请求直接触发时作答：

- `### 篝火讨论 · 独立观点请求`
- `### 篝火讨论 · 定向回应请求`

使用 Runtime 提供的可信请求发送者 Agent ID 作为唯一收件人，不根据显示名猜测，不改投其他成员，不使用 `--to-user`。

需要确认命令时运行：

```text
rovai send --help
```

完成全部思考后，只发送一次：

```text
rovai send --to <请求发送者 Agent ID> --body <完整结果>
```

正文可以不重复书写 `@主持人`。前台如何呈现收件人不改变回复关系。

每条独立观点或定向回应必须一次性完整提交。整条正文目标控制在 200–250 个中文字符以内，最多不超过 300 个中文字符，只保留：

- 核心判断；
- 两项主要依据；
- 一项风险或限制；
- 改变判断的条件；
- 置信度。

不要重复题目、背景或其他成员观点，不发送进度消息。

不要发送：

- “收到”；
- “正在分析”；
- 初步结论；
- 分段进度；
- “请主持人继续”；
- 第二份修订稿。

发送失败时遵循 CLI recovery，不自行盲目重发；当前 Run 的最终输出仍保留同一份完整观点。

## 4. 独立观点

只根据请求中的：

- 用户话题；
- 已确认共同事实；
- 分配给自己的视角；

形成判断。

即使公共 Camp 中已经出现其他成员的结果，也不要引用、跟随或反驳；第一轮的目标是形成独立判断。

```markdown
### 篝火讨论 · 独立观点

#### 核心判断

<1–2 句>

#### 两项主要依据

- ...
- ...

#### 风险或限制

<最重要的一项>

#### 改变判断的条件

<需要出现什么证据或条件>

#### 置信度

高 | 中 | 低
```

不要总结其他成员，也不要代表全体给出结论。

## 5. 定向回应

只回应请求中列出的唯一关键分歧，不重新写一份完整的第一轮报告，也不复述对方观点。

```markdown
### 篝火讨论 · 定向回应

#### 核心判断

维持 | 修正 | 条件化：<更新后的最终结论>

#### 两项主要依据

- ...
- ...

#### 风险或限制

<最重要的一项>

#### 改变判断的条件

<需要出现什么证据或条件>

#### 置信度

高 | 中 | 低
```

证据改变判断时明确修正；不要为了维持角色而假装没有被说服。

## 6. 参与者边界

参与者只负责：

- 独立形成观点；
- 回应指定分歧；
- 提交自己的完整结果。

参与者不得：

- 发起新的 Gather；
- 邀请其他成员；
- 转发当前任务；
- 总结全场；
- 发布《篝火纪要》；
- 自行决定进入下一轮；
- 因看到其他成员观点而主动追加消息。

发送结果后结束当前 Run，等待主持人的新请求或最终纪要。
