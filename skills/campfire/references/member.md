## 回复当前邀请或请求

只在当前 AgentRun 由邀请、定向回应请求或澄清请求触发时回复。使用 Runtime 提供的可信请求发送者 Agent ID 作为唯一 `--to` 收件人；不要改投给其它成员、使用 `--to-user` 或自行转发。Core 会自动把结果的 reply relation 指向这条触发请求。

需要确认发送方式时运行：

```text
rovai send --help
```

用 `rovai send --to <请求发送者 Agent ID> --body <结果正文>` 发送。只有命令 accepted 时才视为结果已建立；随后结束本次响应，等待后续邀请。

## 独立开场

只根据邀请中的话题、分配视角和共同事实形成判断。即使公共 Camp 历史已经出现同场其他人的开场，也不要引用或跟随；保留自己的独立判断。

```markdown
### 篝火讨论 · 开场观点

**话题**

> <当前话题>

**核心判断**

<1–2 句>

**主要依据**

- ...
- ...
- ...

**最担心的失败方式或限制条件**

<最重要的一项>

**希望其他成员回应**

<一个真正影响结论的问题>

**置信度**

高 | 中 | 低
```

从邀请触发的当前 Run 发送给邀请者。标题可以帮助阅读，但可信发送者和 Core 自动建立的直接回复关系才说明你在回答哪一场讨论。

## 定向回应

只回应当前请求指出的一个分岔点，不重新写完整报告。

```markdown
### 篝火讨论 · 定向回应

**话题**

> <当前话题>

**回应的分岔点**

<对方的观点或问题>

**我的判断变化**

维持 | 修正 | 条件性支持

**更新后的核心判断**

<1–2 句>

**关键依据**

- ...

**仍未解决的分歧**

<已解决时写“无”>

**置信度**

高 | 中 | 低
```

从定向请求触发的当前 Run 发送给请求者。证据改变判断时明确修正，不为了维持角色而假装没有被说服。

## 短澄清

Default Lead 只要求确认一句总结时，仅回复该澄清请求：

```markdown
### 篝火讨论 · 澄清

准确。
```

或给出一条最小、准确的替换句。不要借短澄清开启新一轮讨论。
