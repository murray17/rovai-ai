# 双人追问与文档

在提出第一个问题前，完整阅读以下随 Skill 打包的参考：

- [双人追问协议](references/grill-duo.md)
- [领域建模纪律](references/domain-modeling.md)
- [词汇表格式](references/context-format.md)
- [ADR 判断与通用格式](references/adr-format.md)

执行完整的双人追问协议，同时主动维护领域模型。

## 文档例外

“共同理解前不开始实施”仍然适用于产品代码、配置、Migration、脚本和其它交付物。已经明确形成的领域
术语和满足门槛的架构决定可以在会话中立即写入项目文档；这正是本 Skill 的附加职责。

每次写文档前先读取仓库自己的文档导航、`AGENTS.md` 和相关维护规则。仓库规则拥有文件位置、格式、
状态、编号、权威边界和验证命令；随包参考只在仓库没有更具体规则时提供默认做法。

## 会话内维护

- 术语一旦解决，立即更新适用的 `CONTEXT.md`；只记录领域含义，不写实现细节。
- 用户表述与现有词汇冲突时，当场指出并把冲突作为当前唯一决策点。
- 用户描述与代码或权威文档不一致时，展示证据并让用户决定要改变模型还是实现。
- 只有决定同时满足高逆转成本、缺少上下文会令人意外、并且存在真实取舍时才创建 ADR。
- 文档写入后运行仓库要求的文档校验；失败时修复文档，但不要借机开始尚未获准的实现。

最终共同理解摘要同时列出本次新增或修订的领域术语、ADR，以及仍未记录的开放决定。
