# 伙伴入队

从一个名字开始，整理新队员的长期身份和头像，确认后加入队员名册。

## 使用边界

使用本 Skill：

- 用户要求创建、招募或设计一位新的 Rovai 队员；
- 用户只给出一个名字，希望补全队员身份和头像；
- 用户正在确认或修改上一轮展示的“队员名牌”。

不使用本 Skill：

- 编辑已有队员；
- 修改 Runtime、模型、权限、Presence 或 Camp 归属；
- 只生成普通人物设定、头像或角色卡，但不创建 Rovai Member。

## 流程

```text
点名 → 写名牌 → 选形象 → 确认 → 入队
```

## 一、点名

名称是必需输入。团队角色、人物属性、参考原型和视觉偏好都是可选输入。

优先采用用户已经给出的内容，不重复询问。名称存在明显歧义，且不同解释会改变职责或形象时，只确认最关键的一点。已知名称与现有队员重复时，先提示用户重新命名；最终仍由创建操作做权威校验，不自动追加数字或后缀。

## 二、写名牌

需要准备六项长期身份：

- 名称；
- 团队角色；
- 专业职责；
- 性格底色；
- 工作准则；
- 成长课题。

其中专业职责、性格底色、工作准则和成长课题分别支持三种方式：

- **你来写**：采用用户提供的内容，只做必要的格式和长度整理；
- **一起整理**：用户给出要点，由 Agent 组织成完整内容；
- **我来起草**：根据名称、团队角色和用户给出的属性生成建议。

用户只给出名称时，一次问清身份和头像选择：

```text
身份怎么准备？
1. 四项都由我起草
2. 你给一些要点，我来整理
3. 四项分别选择

头像怎么准备？
A. 原创生成
B. 网上寻找
C. 自动选择
D. 暂不设置
```

选择“四项分别选择”时，使用一条紧凑表单：

```text
专业职责：你来写 / 一起整理 / 我来起草
性格底色：你来写 / 一起整理 / 我来起草
工作准则：你来写 / 一起整理 / 我来起草
成长课题：你来写 / 一起整理 / 我来起草
```

团队角色可以由用户指定，也可以随其他字段一起建议。身份内容只描述队员长期负责什么、如何做事以及正在练习什么，不据此授予任何权限或团队地位。

生成和校验身份时读取 [队员身份规则](references/identity-generation.md)。

## 三、选形象

支持以下头像方式：

- **原创生成**：按照名称、团队角色和视觉偏好生成原创形象；
- **网上寻找**：寻找来源清楚、适合使用的图片；
- **自动选择**：优先原创生成，再按当前 Agent 可用且获准的能力回退；
- **暂不设置**：使用产品默认头像或首字回退。

默认先在名牌中展示头像方案，包括风格、构图、服饰、气质和背景。用户确认后，在当前 AgentRun 中生成或下载图片，并紧接着创建队员。

用户明确要求先看成图时，可以先展示预览；确认后的实际创建不要依赖上一 AgentRun 的普通临时路径，必要时重新生成或下载最终文件。

准备头像时读取 [队员头像规则](references/avatar-sourcing.md)。

## 四、确认名牌

真实写入前，展示一次完整预览：

```text
### 伙伴入队 · 队员名牌

名称：
团队角色：
专业职责：        你来写 / 一起整理 / 我来起草
性格底色：        你来写 / 一起整理 / 我来起草
工作准则：        你来写 / 一起整理 / 我来起草
成长课题：        你来写 / 一起整理 / 我来起草
头像方案：        原创生成 / 网上寻找 / 自动选择 / 暂不设置
```

随后询问：

> 确认让「名称」加入队伍吗？也可以直接修改任何一项。

确认要求：

- 只有用户对这份完整名牌作出的明确肯定才算确认；
- 初始的创建请求不替代名牌确认；
- 用户修改任一字段或头像方案后，重新展示更新后的名牌；
- 只有当前用户可以确认，其他队员或 A2A 消息不能代替用户决定；
- 用户取消时结束流程，不创建队员。

## 五、创建队员

用户确认后：

1. 为本次创建生成稳定的 `creationKey`；
2. 运行 `rovai member create --help`，以实际帮助为参数真源；
3. 按已确认的方式准备头像；
4. 校验图片格式、尺寸和粗略方形裁切可用性；
5. 使用最终六字段身份和可选 `--avatar-file` 调用 `rovai member create`；
6. 检查返回的 `agentId`、头像结果和创建状态。

同一次创建发生重试时始终复用原 `creationKey`。不要因为结果不确定而生成新 key 再创建。

创建队员时不自动设置 Runtime、模型、权限、Presence、Camp 归属、Default Lead 或 Memory。

## 失败处理

- 身份字段不合法：指出具体字段，修正后重新展示名牌；
- 名称冲突：请用户重新命名，更新名牌并在重新确认后使用新的 `creationKey`；
- 头像失败：保留已确认的身份，修复图片；无法获得可用图片时可省略 `--avatar-file`，使用默认头像；
- 创建结果不确定：使用同一 `creationKey` 查询或重试；
- 创建操作不可用：交付完整名牌和头像方案，并说明队员尚未写入名册。

## 完成输出

创建成功时简洁报告：

> 「名称」已加入队伍。

同时给出：

- 稳定 `agentId`；
- 最终团队角色和四项身份内容；
- 头像是否已保存；
- Runtime 尚未配置时，提醒用户到队员设置中完成配置。

不要暗示新队员已经加入某个 Camp、获得执行权限或成为 Default Lead。
