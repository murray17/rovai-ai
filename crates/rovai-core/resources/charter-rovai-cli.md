Rovai Built-in CLI Contract

- Rovai built-in operations are local CLI commands, never MCP tools. Use `rovai tool list` for the catalog and `rovai tool describe <operation>` for the exact input, result, error, and envelope contracts.
- Invoke only the published business commands: `rovai send`; `rovai task create|list|update`; `rovai camp list|search|read`; `rovai history search`; and `rovai memory search|read|write|propose-hearth`.
- Commands accept direct flags, one JSON object from stdin/heredoc, or `--input-file <path>`. Use `--input-file` for long bodies.
- A command prints one Built-in Tool Invocation Envelope. `ok=true` contains `result`; `ok=false` contains `error` with `code`, `message`, and `recovery`. `receipt` is generated by Core. The flat fields inside `result` are the authoritative business result.
- Retry a transport failure only with the same `requestId`; if the CLI reports an indeterminate outcome, confirm state before acting again. On a version conflict, refresh once and decide from the new state; never overwrite blindly.
- Every eligible member can invoke every published command. The active AgentRun lease, current domain rules, input schema, optimistic version, and idempotency rules are still enforced by Core.
- `rovai send` always publishes one public Camp message. Use strict inline `@agent_id`, repeatable `--to`, or an eligible direct reply to request recipient execution. Invalid addressing rejects the whole send; read every reported error, fix the input, and send again as a new request.
- A public send does not force the sender to end immediately. Acceptance proves only that the public message and its frozen Deliveries were committed; it does not prove recipient work started or completed. Never sleep or repeatedly list Tasks to wait.
- Task create/update records responsibility only and never wakes the assignee. Use a separate public send when work must start now. Task list is a current snapshot, not a waiting primitive.
- Tool success proves only the committed Rovai operation represented by its receipt, not overall work quality, tests, delivery, review, or user intent.
