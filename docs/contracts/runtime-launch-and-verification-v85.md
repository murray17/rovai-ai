# Runtime Launch and Verification v85

继承 [v84](runtime-launch-and-verification-v84.md)。本版只增加本机安装版本按需刷新，版本结果不参与 Host 生命周期。
检测按钮、模型目录、正式初始化、认证与会话接续各自的职责保持。
不查询远端版本、不下载安装、不修改用户原生配置。

## 按实际目标读取

Run 已选定实际安装与 Host、进入正常执行流程后，可以向现有 Check Manager 提交轻量版本请求。
提交不等待锁、版本命令或其他 Host 关闭；不是创建 Run、获取 Host 或发送输入的前置条件。
仅查询该安装、程序路径与实际捕获的启动环境，不扫描全部 Runtime，不切换安装副本。
同一目标由现有进程内检查记录共享最近实际尝试时间；自动尝试最小间隔十分钟，成功和失败（含实际入口读取失败）均计时。
未到期跳过；没有 Run 就不触发，不增加定时任务或持久化记录。
正式入口被替换或保存新的程序路径时，删除被替换入口的尝试记录；当前入口的不同有效启动环境仍分别限频。
旧读取不能重新建立已删除的记录；切回原路径建立新记录，原选择期间的迟到结果不能写版本或标记 Host。
清理入口记录不删除活跃 Run 已实际读取过版本的事实，该事实沿既有 Run 收尾清理，避免本轮追加查询。

手动检查绕过该间隔。相同目标、用途与既有合并条件匹配时，手动和自动请求共享在途读取。
整体重扫继续原有并行流程，已有正式启动继续原有调用，不为统一所有入口重建调度或强制全局单飞。
本轮正式启动已经实际读取版本时，成功或失败都不追加自动查询；命中历史版本缓存不算实际读取。
手动、重扫及已有正式启动的实际读取均登记尝试和结果顺序，草稿检查除外。

沿用适配器命令、解析、启动环境、容量限制与十秒版本命令上限，不增加重试、认证预检或目录查询。
成功按原有身份围栏保存安装版本。自动失败只记录日志，不改安装可用性、不发布失败诊断、不影响 Run；
同一次读取有手动等待者时，仍向手动请求返回并在原位置展示具体失败。
未保存草稿独立检查，不更新正式安装、不更新正式目标的限频/结果顺序、不触发 Host 退役。

## 结果顺序与目标归属

实际读取开始时，登记同目标的递增顺序；提交时在原有安装、入口、配置校验内核对顺序。
较新结果已接纳后，较早结果不得写回版本；静态缓存发布不得覆盖同身份当前已保存的版本。
不比较版本大小，不保存读取历史；不同安装或有效启动环境的结果不混用。
路径或文件指纹变化仍按原有安装完整性规则处理，不扩展为全局兼容性重构。

## 版本与 Host 生命周期解耦

成功的后台、手动及正式启动版本读取只保存安装信息，不标记 Host 退役，不改变复用资格，
不新增后继等待或原生 Session 占用拒绝。版本字符串更新本身不制造配置失效或强制进程更换。
不捕获仅供版本退役使用的 Host 基线，不增加自动退役配置开关。

健康旧 Host 按原有规则复用；原有取消、故障清理、协议异常、配置失效、TTL/LRU、用户停止与正常关闭保持。
OpenCode 原有插话后的关闭语义不变，不能把必须关闭的原因改成后台工作保留。
只有原有生命周期需要新建 Host 时，才使用当前选定入口并沿正常 Native Session 接续；
不删除对话、清空历史或用空白会话隐藏恢复失败，不自动切换安装副本。

安装版本更新不回写正在运行的 Host 或当前 Run 的实际版本，也不将版本加入 Native Session 身份。
不承诺升级后的下一条 Run 或十分钟后一定使用新版。程序自身故障、外部原地升级破坏文件和原有启动/接续错误
仍走已有处理；本功能不增加回滚、自动重试、后台监控、队列或恢复框架。

Pi 默认使用相同规则，不预置升级退役例外。真实升级验证必须证明在同一入口原地替换安装后，
空闲 Warm 和活动 Run 两种时机都继续使用原 Host/PID 完成应答、上下文与实际工具操作，再验证正常关闭后的新版冷接续。
升级提示本身不作为失败；如有可归因的升级故障，先核对已有失败清理和冷启动恢复，另行说明最小修正。
Hermes 共享 Gateway 不属于本功能管理范围。
