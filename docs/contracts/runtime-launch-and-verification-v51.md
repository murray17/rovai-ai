# Runtime Launch and Verification v51

继承 [v50](runtime-launch-and-verification-v50.md) 的原生配置归属、凭据编辑、执行、权限和恢复边界。
本版将 Claude Code / Codex 启动与 API 设置的保存收窄为一次本地提交；覆盖继承版本中的保存后发现、
模型元数据命令、同页来源自动确认及列表刷新要求。其他 Runtime 共用启动设置保存入口时同样不自动检查。

## 本地提交

`runtime.startup.save` 成功只表示本次提交字段通过必要本地校验并写入正确来源，返回已提交设置和修订。
它不证明连接、凭据、模型可用，也不证明当前进程已应用配置。保存不得触发或等待 Shell 环境读取、PATH
搜索、Runtime 发现、CLI/version/models 命令、账号/Provider 查询、Token 刷新、Host/Session 重启或预热。
不得把这些步骤改成保存后自动启动的后台任务。

保留字段/格式校验、显式新程序路径的本地文件检查、来源身份、revision/CAS、外部修改冲突、未知字段保留、
原有安全写入与读回确认。沿用原生 JSON/TOML、Key 引用和 Keep/Replace/Clear，不迁移凭据到 Rovai 数据库。
写入来源只使用显式选择或已经发现的入口；未知或冲突来源报错并保留草稿，不补跑发现或猜测目标。
单独保存普通启动字段仍允许连接来源未确认；同时编辑新来源与 API 时沿用先提交启动选择、保留 API 草稿的边界。

Codex 模型列表继续本地校验 ID、唯一性、默认项。已有原生目录保留隐藏元数据和未知字段；没有目录时使用
已有的原生兼容默认结构生成用户明确编辑的列表，不查询可用模型或声称 Provider 能力。目录本身的并发校验保持。

## 修订与执行隔离

保存仅发布已捕获环境加新配置的内存快照，并按现有规则更新配置修订、安装/目录失效标记和本地缓存。
`reconnectRequired` 保留既有 wire 字段，表达后续执行不得复用旧连接身份；它不是保存请求中的重连指令。
当前 Run 按既有生命周期收尾；后续 Run 的配置冻结、原生来源摘要与 Host 兼容检查继续隔离旧配置。

环境捕获和发现文件校验不得持有保存需要的提交锁等待外部工作。它们在提交时重验代次、合并最新保存字段，
旧检查不得覆盖新修订。读取、检查、模型刷新和正式执行入口仍各自负责原有工作，保存不自动调用它们。

## 回执与界面

保存成功、无操作回放以及冲突中的 `latest` 都不包含 `credential.value`。显式 Owner `get/observe` 的
静态 Key 读取仍由 v50 拥有；编辑器只在来源及凭据修订匹配时保留已有内存值，或保留本次已提交的替换值，
清空已提交 Key 草稿并恢复隐藏，不为回显再次读取。日志、诊断和持久执行证据继续不含完整 Key。

前端收到回执后更新表单基线并结束加载，显示“已保存”；若只提交了启动选择，明确连接草稿尚未保存。
父回调、全局刷新和来源观察 effect 不得把列表重载或 native 检查串回保存。页面进入或用户显式重试的可选
观察仍独立存在；其迟到响应不得覆盖保存或用户草稿。后续视图读取失败不得改称保存失败。

## 验证边界

确定性测试必须覆盖 URL、Key、模型及普通启动字段的单次本地提交、无额外环境捕获/发现/子进程工作，
被屏障阻塞的环境读取与检查不妨碍保存，迟到结果合并/代次拒绝、冲突/写入失败/未知字段/凭据三态，
以及旧连接快照失效。前端以请求计数和受控回执验证立即结束加载及草稿保留，不以一次手工耗时作为证明。
