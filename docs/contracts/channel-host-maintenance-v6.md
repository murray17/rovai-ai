# Channel Host Maintenance v6

继承 [v5](channel-host-maintenance-v5.md) 的 Host 权限、单事务 tick、FIFO、Outbox lease、终态收口和按需 watchdog。
本版统一飞书、Lark 和钉钉父群名单的查询时机，补充 [Channel Message Bridge v1](channel-message-bridge-v1.md) 的入站与投递流程。

## 入站、绑定与派发

- 普通群只有主人在群里 @ 机器人，以及确认绑定项目或快速对话，会触发平台名单查询。Host 先用 `requireFreshRoster` 向 Core 提交原入站聚合。Core 发现名单的 `observed_at` 早于或等于该消息首次入库的时间，才返回 `channel.roster_sync_required`。同步后重提同一条消息。重复回调和重启恢复使用同一判断。
- 同一渠道、租户、父群共用一轮在途读取。飞书和 Lark 每个已发布机器人各查一次 `isInChat`。Core 只写本轮成功的在群或离群结果，其余机器人保留上次状态。有一个成功结果即可更新群的 `observed_at`。实际收到有效群消息的机器人在 finalize 时直接记为在群。
- 钉钉用一个机器人读取全群。当前应用未安装或缺少接口权限时，换下一个已发布机器人。限流、网络与服务端故障结束本轮。缺少名单数组表示读取失败，明确返回空数组表示该次查询未发现群机器人。
- 全部读取失败时，同群后续读取受 5 秒、15 秒、60 秒、5 分钟的退避约束。单条入站消息最多等一次退避重试，随后使用本地名单和实际收件机器人继续处理。失败不会把任何机器人标为离群。明确的权限与凭据错误记录在诊断日志和设置页对应的机器人行。
- 确认绑定前先在本地校验卡片，再查目标群，提交时复核卡片。整轮读取失败时保留原卡和按钮，并提示用户稍后再点。
- 普通群桌面输入、转派、出队、重试均直接按本地成员派发。已排队的渠道请求若在准入时确认目标已离群，向群内发送现有失败提示。绑定群中收到明确的进出群通知时，只更新该机器人并立即同步线程成员。未绑定群的通知只记事件。话题群保留既有的父群 `requiredRosterGeneration` 投影流程。
- 空闲、启动、重连、打开设置或机器人增减均不扫描历史群。无业务时，名单查询为零。

## 接入与取舍

群内 `/new` 和没有 @ 机器人的消息在群资料与名单查询前拒绝。飞书和 Lark 恢复 SDK 原生合并转发展开。如果平台投递了没有 @ 的合并转发，SDK 过滤前可能读取一次消息详情，名单查询仍为零。一次群资料请求同时读取群名与群类型，成功结果在内存缓存 24 小时。失败时可以沿用上次的成功群名，占位名不落缓存或数据库。设置页显示本地上次验证时间。连接、发布、改配置或恢复缺失凭据时再检查网页身份。同一套凭据共用在途令牌请求，切换凭据后重新获取。钉钉仅恢复 Stream 时不发测试卡。

群名单允许短时过期，以下一条有效 @ 消息或下一次进出群通知校正。飞书、Lark 离线期间可能错过退群，钉钉也可能没有通知。在下一条 @ 之前转给该机器人的任务可能在本地执行一次，群回复按普通发送失败处理。
