# Runtime Launch and Verification v89

继承 [v88](runtime-launch-and-verification-v88.md)。本版只修正按需刷新对当前安装入口的解析，
不恢复版本驱动的 Host 退役，不改变模型目录、认证或正式协议处理。

## 当前安装与驻留进程

智能体设置中的版本行表示当前选中安装的已读取版本；驻留 Host 和 AgentRun 保留各自的启动身份。
后台请求由使用该 Runtime 的 Run 触发，但不能把旧 Host 冻结的 canonical 路径当作当前安装入口。

到达既有十分钟尝试间隔后，在后台沿当前 Runtime 的既有发现规则解析一个入口，再读取一次版本。
只解析这一种 Runtime，不全量重扫；保留已捕获的有效启动环境、适配器命令和十秒执行上限。
例如 Homebrew 稳定链接从旧 Cellar 目录转向新目录、旧程序仍存在时，应读取新链接目标并更新安装版本。
显式设置的稳定链接同样重新解析；用户明确固定旧版本绝对路径时，继续尊重该路径。
手动／自定义入口的既有归属和缺失入口 fallback 保持；一旦选定入口，版本读取失败不再尝试其他副本。

已有 Host 仍对应同一安装时，Manager 按当前安装目标和捕获环境判断限频与同用途合并，
不因 Host 留有旧 canonical 路径就拒绝后续后台请求或把新入口视为每轮均需查询。
入口检查已实际尝试后失败仍计入间隔；缓存命中不计为实际读取。
解析得到不同目标时，实际版本命令按该目标登记读取顺序，提交仍核对原安装、搜索代次和程序身份。
正式提交新入口后沿既有流程清理旧入口记录；较早或不同归属的结果不能覆盖新结果。

成功通过原安装／发现发布链路更新版本行；自动失败仍只记日志，保留符合原规则的已知安装信息，
不把本次 Run 判为失败、不新增检查反馈区域。手动等待者沿现有链路得到具体错误。
不增加定时任务、重试、队列、锁、缓存体系、数据库表或安装副本轮询。

本版不调用 Fleet 退役或失效接口，不改变获取、释放、清扫及原生 Session 接续。
当前入口确实变化时的原有身份与冷启动处理保持，不能仅因版本文字更新制造配置变化。
安装版本更新不回写旧 Host／当前 Run 的运行版本，也不承诺触发刷新那一轮已经使用新版。
