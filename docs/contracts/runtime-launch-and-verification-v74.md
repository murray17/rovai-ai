# Runtime Launch and Verification v74

继承 [v73](runtime-launch-and-verification-v73.md)。本版统一全部 Adapter 的模型目录兼容与执行边界，
替代历史合同中依据模型目录拒绝显式配置、要求 Ready 必须有目录默认项、自动过滤覆盖值、
只打开 Picker 才读取目录和在保存值前附加“尚未核对”的规则。

## 目录归一化

共享 Adapter 层按原生模型 ID 合并重复条目，保留原生 ID、显示名称、描述、元数据及可用选项。
同一参数合并去重选项；原生 current/default 值可补充枚举。空 ID、无效单条模型、参数或枚举只在该条
处理，不使其余有效目录失败。兼容处理适用于 ACP、Codex、Claude、Pi 和 Antigravity，不为 Copilot
的重复 `auto` 建立特殊分支。内部 Runtime Default sentinel 不作为可选原生模型。
单条模型的非对象元数据局部忽略，保留模型；重复条目的有效元数据仍参与合并，Adapter 补充字段不整体替换
已有有效元数据。

完整响应无法读取、没有可用目录或查询失败时，不推进目录成功时间，不清空已有有效目录、模型或参数。
沿用现有缓存身份与失效规则；同一身份下的健康检查即使没有目录也不覆盖有效目录。读取目录的成功
与原生 Session 可用分别判断，不凭目录缺少默认项或当前模型否定可用 Session。
健康失败的 `stale_at` 不否定已有目录。真正的安装、程序或有效配置变化，在现有失效事务中清除
目录成功时间；同身份的健康/版本/静态快照补写保留成功目录，不比较健康与目录的时间先后。
进程内搜索代次的启动重记不清除目录；共享输入经 `same_inputs` 确认变化时才清理共享目录，配置保存继续按 Runtime 定向清理。

模型目录首次读取、健康失败或目录失效均直接进入现有原生目录读取，不先要求完整检查成功，也不在缓存未命中时
升级为完整检查。必要初始化、协议要求的认证和空会话、模型及参数查询保留；不附带独立认证状态放行或能力演练。
Claude 直接使用既有 `list_models` 和明确不支持时的兼容处理；Codex 目录不以 `account/read` 判断放行，完整检查中的认证保留。
目录沿用现有 JSON、独立目录成功时间、TTL 与安装／入口／配置归属，读写和展示不依赖健康 Ready 或 authenticated。
健康失败不能使同目标的有效目录变成读取失败；入口或配置实际失效仍使原目录不能冒充当前目标。
目录成功只更新目录字段；失败通过对应请求返回脱敏原因，保留已保存模型和参数、有效目录及历史完整检查记录。
检测行和模型选择位置分别消费本次轻量检查与目录请求结果，不回填历史 Probe 错误，不增加提示区域。

### CodeBuddy 原生档位

CodeBuddy 模型选项保留原生键 `thought_level`。逐模型 `_meta.effortOptions` 的 `value` 为保存和下发值，
`name` 为显示名称；明确的空列表不以其他来源补齐。该字段缺少时，只为 Session 当前选中的模型提取
已有 `configOptions.id=thought_level`，不得复制到其他模型。没有数据不猜测，也不补入默认覆盖值。
此转换不新增 Probe 或模型切换；已保存值沿用现有保留和透传语义。队员摘要、消息投影与 Renderer
一致读取该原生键，公开消息字段仍为 `reasoningEffort`，不改变已有配置或数据库 shape。

## Windows 标准包装入口的包身份

已明确识别的标准 npm/pnpm `.cmd` 在原启动脚本与系统解释器身份上追加目标包的规范路径和有界
`package.json` 内容摘要，并核对包声明 bin 与脚本目标一致。只读取静态文件，不绕过原 `.cmd` 启动，
不从 manifest 代替 CLI 自报版本，也不扫描整个 node_modules。此身份覆盖正常包版本/manifest 与路径
变化，不声明覆盖同一 manifest 下任意内部文件的替换。

采集、快速复用判断和发现/检查/目录发布前复核使用同一包身份；不能因 `.cmd` 属性未变跳过依赖核验。
包在操作期间变化或无法复核时沿用既有 Superseded/错误路径，不把旧结果归给新包。未知自定义
`.cmd/.bat` 保持原行为；已识别标准包的身份读取失败不得静默回退到旧弱指纹证明未变。
不新增检测触发、进程、后台任务、缓存、数据表、全局运行门禁或健康 Warm Host 退役策略；
指纹变化后的版本补读和能力/目录失效继续遵循原规则。Codex 的原生目标解析保持独立。

## 明确配置由原生 Runtime 接受

模型目录只用于发现和选择，不是保存或执行的准入表。显式模型 ID 与已设置参数按原生协议传递；
不以目录缺失、未枚举 ID／参数／值或 setter 未回显目录阻断执行。不从目录补入默认值，也不按目录
删除用户覆盖值。Runtime Default 仍省略显式模型参数，内部 sentinel 不发送给原生 Runtime。

Adapter 保留原生协议必要的数据映射、真实 RPC/进程错误及原生执行结果；原生拒绝的配置不静默改为
其他模型或参数。Codex 将字符串 `reasoning_effort` 原样映射到 `effort`，不按目录枚举限制其值；
本轮不对未知键或异常类型增加启动拦截，无法表达的异常输入留待后续完善。
冻结配置中的 `serviceTier` 是系统费用审计字段，不参与用户模型参数判断，不作为原生发送来源。
Fast 沿用 `camp_fast → serviceTierForTurn`：开启传 `priority`，关闭传 `default`，未设置时省略；
默认模型与显式模型共用此路径，不向原生请求发送持久 `serviceTier`。
不同来源的模型按用户选定来源处理。健康或目录检查不增加模型调用、用户审批或
额外执行流程；明确的单个 Provider／模型原生拒绝只影响其自身信息。MiniMax 刷新中的进程退出、
连接或协议失败与整轮超时使整次刷新失败并保留旧目录。沿用既有日志，不新增审计存储。

## 用户界面

可见参数页按需读取目录，模型与强度共享一次请求及临时状态；缓存有效时直接复用，隐藏页与普通 Run 不读取。
访问时核对已有 `revalidateAfter`；同一观察的共享缓存状态不被本地旧 Fresh 覆盖。
DSH 在缓存未命中后先复查页面与目标归属，再追加原生读取。引导页直接返回目录结果，共享安装投影另行刷新，其失败不改写目录结果。
目录成功时间独立于健康状态；读取与写回不要求完整检查成功，同身份版本补写不清空目录，真实安装、程序或有效配置变化仍使旧结果失效。
目录请求与完整检查用途隔离，失败不追加完整检查，不改变安装可用性或保存、执行门槛。完整诊断已取得的目录在后续失败时仍可按当前身份写回，诊断失败保持。
已存模型和强度直接显示原值，不附加“尚未核对”。目录读取失败或 deferred 不显示错误详情、失败摘要或环境更新说明，保留同身份已有候选。
首次无目录时显示原生默认项、已保存值和手工模型 ID 输入，不硬编码替代清单。
模型菜单搜索框右侧固定刷新图标是唯一目录刷新入口，读取时原位旋转且不能重复点击；首次无目录可显示中性加载占位，
已有列表刷新不插入状态行。关联参数沿用现有下拉与加载指示，不增加独立刷新按钮或重试行。
`runtime.modelCatalog.open` 的可选 `forceRefresh=true` 绕过新鲜缓存短路，启动或加入当前目标的一次轻量读取，
不清空历史、跳过身份检查或升级完整诊断。普通访问仍遵守新鲜度，DSH 的 `cacheOnly` 优先且始终只读本地。
加载期间列表继续可操作；保存、运行自身的失败仍沿用原有反馈。
成功、失败、空结果或 Pi unknown 均结束本次自动尝试；目录时间、metadata、保存状态与共享投影更新不触发新读取。
保存的未枚举参数可更改或清除。同一 Runtime 内切换显式模型时保留显式覆盖值，
切换到 Runtime Default 则按用户选择清除覆盖值。异步目录更新只更新候选项，不改写草稿或已存配置。

## 本机配置的局部故障

`runtime_startup_setting` 按 Runtime 单独读取、解析和校验。无记录沿用自动发现；已有记录不可读取或格式无效时，返回该项的 `configuration.configurationError`，保留原始 JSON 与 revision。该项不产出默认发现候选、不读取默认原生凭据，其余 Runtime 正常加载。错误不进入新的数据库表或恢复队列。

Owner 设置入口仍返回损坏项的版本与明确错误，不能将默认外形的错误投影解释为有效空配置。显式重新选择程序或恢复自动发现时，以 `expectedRevision` 加 `programPath` edit 通过既有 CAS 替换；旧版本拒绝，不对坏 JSON 做字段合并。保存刷新现有 Runtime 状态，用户可在同一 Core 检查及使用修正项。

字段编辑遇到 revision 不符时返回既有 `status: conflict`、`latest` 和字段冲突；页面更新版本基线并保留草稿，用户解决冲突后可以继续保存。不能只返回“再次保存”错误而让页面一直持有旧版本；提交时的 CAS 仍保留。

通用环境变量单条不可解密时，管理入口返回 `commonEnvironment.error` 与原 revision；执行和检查保留该项不可用语义，不回退到其他账号。用户重新填写后沿用既有 revision 校验追加新版本，保留损坏旧记录；未修改的错误投影不得被提交为空值。原本不继承通用变量的独立队员仍按既有规则使用自身环境。

## ACP 冷恢复收尾

本次恢复调用链传递最终成功的原生 RPC 方法。成功 `session/resume` 在必要配置完成后，
通过已有精确 Session route、Host/Run/epoch owner 与 LoadingReplay 状态校验直接进入 Ready，
不等待历史重放 grace 或 quiet window；不能重新 bind Ready 覆盖错误状态。
成功 `session/load`，包括 resume 的 `-32601` 后降级 load，保留既有有界迟到历史隔离与收尾。
返回其他 Session ID、错误 route/owner、协议异常仍拒绝；当前输入 ACK、不重放和同 Host 复用边界保持。
实际方法仅在本次调用内传递，不新增协议字段、数据库字段或恢复状态。

## 冷启动刷新的失效范围

为本次启动刷新程序身份时，不再调用整类 Adapter 失效，不主动停止或标记退役同类型的其他健康 Host。
Codex、Pi 与已有驻留复用的 ACP Adapter 由 Fleet 实际 acquire 决定复用；只有其创建进程分支才检查
磁盘程序、刷新身份及读取必要版本。健康 Host 保留启动时的程序身份，磁盘升级本身不参与 Host 兼容摘要；
安装、账号、配置、工作区、MCP 与 Native Binding 的原有兼容约束保持，不能用缓存记录或历史 Ready 代替 acquire。
ZCode 的 warm 摘要只读取用户配置；随程序发布的安装包与内置 Provider 数据归冷启动文件检查。

实际取得 Host 后，复用现有 Runtime rebind 在 `runtime_initializing` 且尚未 dispatch 输入的边界一次确定
本轮程序证据。原 version 校验隔离旧 epoch，既有输入提交检查阻止改写执行中的 Run；不新增状态或持久表。
用户选择的模型、权限及账号不变，不借程序刷新切换 Native Session。停止、安装禁用／删除及必要配置变更
继续使用原失效路径。Claude、Antigravity，以及完成后关闭 Host 的 Kiro、Cursor、Hermes 保留原启动检查；
不为它们新增驻留能力。

## Claude 结果与局部问卷拒绝

当前执行的有效原生 success 允许最终文字为空；空文字不等于缺少当前最终结果。
共享 Run 结算不再要求非空文字或先前公开发送。保留已有消息、文件和产物；公开及单聊消息路径
跳过空文字，沿用成功状态与队列推进，不制造答复、不借用旧文本、不重试或额外调用模型。
原生失败、错误 Session、缺少当前最终结果与取消仍沿用原判断。

Claude 不支持的问卷仍在当前控制请求处拒绝，并提示通过普通对话询问；请求 ID 集合只承担重复请求去重。
拒绝后的 Run 按最后有效原生结果结算，诊断不再覆盖成功；取消、普通权限审批与失败结果保持。
此规则替代继承合同中 Claude 的问卷终态覆盖，不改变其他 Runtime 的问卷处理。

## Claude 原生结束与清理

替代继承自 v45 的 result 后缺少 Session 状态 10 秒、轮次间等待 idle 600 秒失败规则。
收到 result 只保存该段结果并继续读流，不启动业务收尾计时；追加输入等待首个输出时仍可执行、可停止。
新输入实际写入时使先前已观察的 result／idle 失效；后续前台活动使先前缓存的最终结果失效，
不得以旧 success 结算没有终态的新工作。原生有效 result／idle、前台活动、权限与后台任务继续决定关闭 stdin。
原生自行退出时收完输出，按最后有效结果和真实退出状态结算，无需再等 idle。
逐条接收回执与 Run 结果独立；未确认的补充输入不成为成功门槛，也不自动重发。

初始化、stdin 写入、确认结束后的进程退出、根进程退出后的输出收集及取消／回收期限继续保留。
仅原生已确认工作结束时，退出期限才可进入强制资源回收；由该回收产生的退出信号不替换原生结果。
进入收尾清理的事实在发出终止请求前记录，与清理调用是否成功分开；部分清理报错不能把已发出的信号误算为原生执行失败。
stdout 已收完且执行成功时，残留清理句柄不推翻结果；实际读写错误、缺少最终结果、原生失败和未经
清理触发的非零退出仍报告失败。清理未确认复用既有标记与回收路径，不增加恢复服务或自动重跑。
已有有限执行预算继续生效；未配置总时限且原生仍未结束时保持运行，由用户停止，不增加适配器业务超时。

## Grok cwd-only Session 参数

Grok 的 `session/new` 与 `session/resume` 都发送 `additionalDirectories=[]`；实际 `cwd` 保持原工作区。
`1.0.70` 原生端拒绝 new 的非空目录数组，空数组与省略字段均接受；采用空数组与现有 resume 一致。
本规则替代继承合同中要求 Grok new 发送附件根和 Run tmp 的规定，其他 Adapter 的目录参数保持。
新建时完整 Bootstrap 仍仅通过 `_meta.rules` 发送；恢复时不重新注入。原生配置、MCP Plugin、Session
身份及 Run tmp 环境绑定保持原语义；不新增重试、协议错误豁免或文件访问替代机制。附件与临时文件
可访问性须通过实际任务单独验证，不能由空 Session 创建成功推断。
