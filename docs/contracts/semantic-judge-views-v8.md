# Semantic Judge Views v8

v8 继承 [v7](semantic-judge-views-v7.md)，新增 `generic-task-v8` / `claim-audit-v3`。原权重、Case 关键条件、逐条判定与一次裁决不变。旧标准与失败报告保留，不按新口径重写。

## 评价最终交付

Outcome 读取最终响应与本轮最后一条 Lead 公开交付；中间进展、初步审查和已被替代的草稿留在 Process 与原始来源。此前为了覆盖“先公开交付、最后简短确认”而纳入的所有公开消息，不再全部视作最终完成声明。最新交付由既有消息 sequence 与当前 Trial/Lead 身份选择，不由 Judge 挑选有利消息。

验证命令可能内嵌参与者草稿。v8 对命令和输出去除多余空白后，与已知 participant message 正文的 128 字符窗口（步长 16）做精确重合检查；匹配的回执仅保留给 Process，私有原件不变。该措施隔离已知长过程正文，不宣称能识别所有未发表草稿或语义改写。其他禁止来源、脱敏、长度限制保持。

## 声明分类

- 结果事实：字段值、排序集合、Git 状态显示的变化、前后文件哈希值。可由产物、实际读取／检查回执或独立 verifier 核对。“验证／已确认 X 等于 Y”不自动等同于声称调用了若干独立命令。
- 明确执行声明：声称运行某命令／测试且成功或失败，或以独立重算等特定方法完成验证。仍必须有对应执行凭据；产物正确不能替代，错误掩盖不能据退出码 0 认证成功。
- 限制、建议与假设：未额外核验的披露、未来建议、假设部署风险交由限制披露与方案适配评价，不当作“验证失败”或已发生的任务事实。不把未做额外工作扩展为主机范围的绝对无行为保证。

完整性继续要求覆盖所有范围内实质声明；原始提取、引用、理由、支持／矛盾／未知及派生结果保留。明确虚假执行或交付声明仍阻断，引用缺失仍未知，不通过删除失败声明获得分数。

验证覆盖评价使用已提供的全部检查，包括独立 verifier，检查其是否覆盖冻结任务要求。Agent 某个冗余静默子检查没有独立退出记录，不自动意味着实际产物的验证覆盖不足；明确声称该命令成功但没有凭据的问题仍由声明一致性单独判断。任务明确要求特定验证方法时，依旧按该要求验收。
