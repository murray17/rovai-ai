# 操作指南

这份指南从配置第一位队员开始，介绍 Runtime、权限、对话、Skill、MCP、运行监控和团队记忆的基本使用方式。

安装与首次启动见：[安装指南](installation.md)。

## 1. 配置队员

名称、头像与职责帮助识别队员和分工；智能体、模型与权限决定执行能力。

### 用 Member Studio 创建

在会话中描述名字与工作要求，例如：

```text
创建一位叫“知微”的队员，负责拆解复杂问题、核对证据并提出建议。
```

Member Studio 会起草名称、角色、职责和性格，供你修改或确认；确认后才创建队员。工作准则与成长课题默认留空，提供内容或明确要求时才补充。指定角色或外观时会主动提出对应头像方案，没有外观要求时可以使用默认头像。预览按需提供。

### 在队员工作区完善配置

- **身份信息**：名称、团队角色和专业职责。
- **头像**：点击“更换头像”，上传图片后裁切并确认，再保存身份信息。非正方形图片也支持，预设头像仍可选。
- **更多设定**：性格底色、工作准则和成长课题默认收起，已保存内容继续生效。
- **运行配置**：选择智能体、模型、权限与运行参数；与身份信息分别保存。

创建队员不等于配置好执行环境或加入当前会话。智能体未配置时，可在队员设置的“运行配置”中继续完成。

首次组队可从两到四名队员开始，让探索、质疑、推进等职责清楚分工。

## 2. 选择 Runtime 与模型

在队员的「运行配置」中选择：

1. Agent Runtime；
2. Runtime 安装；
3. 模型或 Runtime Default；
4. 推理强度等可用参数；
5. 权限模式与沙箱设置。

`Runtime Default` 不依赖模型目录，可以直接使用。显式模型需要 Runtime 已完成可用性检查，并返回当前模型目录。

切换 Runtime 不会自动把旧 Runtime 的模型和权限语义套到新 Runtime 上。保存前应重新检查当前字段。

## 3. 权限怎么设置

如果是在**你自己的、可信并且可以恢复的项目目录**中工作，希望队员尽量少被权限弹窗打断，可以使用最高权限模式。

最高权限通常允许 Runtime 修改文件、运行命令，并减少逐次确认。启用前建议确保项目已有 Git 提交或其他可用备份。

对于陌生仓库、下载的第三方代码、包含敏感文件的目录，先使用默认、询问或计划模式，不要直接开启最高权限。

### 各 Runtime 的高权限配置

| Agent Runtime | 高权限配置 |
|---|---|
| Claude Code | `permission_mode = bypassPermissions` |
| Codex CLI | `sandbox_mode = danger-full-access`；`approval_policy = never` |
| OpenCode | `permission = allow` |
| GitHub Copilot CLI | `allow_all = on` |
| Antigravity | `mode = accept-edits`；`sandbox = off`；`dangerously_skip_permissions = on` |
| Kiro CLI | `trust_all_tools = on` |
| Qoder CLI | `permission_mode = bypass_permissions` |
| CodeBuddy | `permission_mode = bypassPermissions` |
| Qwen Code | `approval_mode = yolo` |
| TRAE CLI CN | `permission_mode = bypass_permissions` |

权限决定 Runtime 原生工具可以做什么。Rovai 的审批、运行记录和可观察性不能代替操作系统权限、Runtime 沙箱或项目备份。

## 4. 创建对话

对话围绕一个真实项目、任务或长期目标建立。

创建时重点确认：

- **名称与目标**：用一句话说明这支队伍要解决什么；
- **项目目录**：选择队员实际工作的目录；
- **队员**：只加入与当前目标有关的伙伴；
- **Lead**：选择默认负责接住任务和整理结果的队员；
- **协作方式**：决定是直接对话、双人追问，还是集体讨论。

项目目录可以是普通文件夹、空 Git 仓库或已经存在提交的 Git 仓库。Git 能力会按目录实际状态动态启用，不是创建对话的必要条件。

### 使用团队或自定义组合

“团队”页面可以保存常用队员组合、队长和可选的团队指引。通过下拉框添加队员，队员行上的
“设为队长”和“移除团队”负责调整分工；已有团队也可以复制后修改。

新对话的选择器把“自定义”放在第一项，允许当场选择队员和队长；选择已保存的团队时，直接使用
该团队的配置。团队修改只用于之后创建的对话，已有对话仍保留自己的队员和创建时的指引。

在“设置 → 通用”中选择一键创建使用的团队或自定义配置。自定义配置独立保存，不要求创建团队；
升级前保存的配置继续作为自定义使用。删除当前默认团队会关闭一键创建，保留原自定义配置。

## 5. 在对话中分配工作

### 直接发送

不指定队员时，由当前对话的默认 Lead 接住任务。

### @ 指定队员

需要特定角色处理时，直接在消息中 @ 对应队员。例如：

```text
@叮叮 先调查现有实现和相关文档，整理三个可行方向。
@芝士 检查这三个方向里最容易被忽略的风险。
```

### 引用项目文件

在已绑定项目目录的公开对话中输入 `@`，再输入文件名或路径片段。匹配结果按队员、文件、对话、使命分组，
也可以手动切换到“文件”筛选。选择文件后会直接回到编辑，输入框显示文件类型图标和文件名；
同一条消息中有不同目录的同名文件时，会补上最短可区分目录。

点击引用可打开文件预览；通过右键、键盘选中后 Shift+F10 或触屏长按可查看完整路径、重新选择或移除。
项目文件树和文件预览也提供“引用到输入框”。移除引用不会删除源文件。

文件引用保留在草稿、输入历史和失败恢复中。同一有效根目录内跨对话粘贴会重新确认目标身份；
无法确认时保留路径并提示重新选择。发送前文件已删除、根已变化或不能读取时，会保留整份输入并标出问题。

可以只发送文件引用来接续已有任务。引用表示队员能按路径查找材料，文件内容由队员按需读取；
发送后文件修改会影响之后的读取。需要固定某次内容时，请另行保存版本。
Desktop 和已认证 Web 使用相同的项目文件能力。首版不包含单聊、目录或行范围引用。

### 使用附件

可以把文档、图片或其他任务材料加入对话。本地文件保留原路径引用，队员按当前执行环境和权限读取；发送后应保持源文件可用。

不要把密码、Token、私钥或其他凭据作为普通附件发送。

## 6. 选择合适的协作方式

### 普通会话

适合目标明确、由一名队员主导推进的任务。

### `grill-duo`

适合方向模糊、需要补齐约束或需要独立反证的决策。

一名队员负责持续追问，另一名队员从不同角度检查事实和风险。最终决定仍由用户作出。

### `campfire`

适合需要整支队伍参与、没有唯一答案的问题。

队员先分别给出观点，再整理共识、分歧、证据缺口和下一步选择，避免最先发言的人过早影响所有人。

## 7. Skill 支持

设置中有两个入口：

- **Skills**：选择 Runtime，查看它在执行端的用户级原生 Skill。支持搜索、刷新、复制入口路径和只读文件预览；安装与管理使用对应 Runtime 的原生方式。
- **工具箱**：为队员选择 Rovai 提供的协作 Skill。可搜索队员、逐项勾选，或对当前筛选结果全选；“查看说明”可阅读用法。

在对话输入框键入 `/`，可以选择全队已配置的工具箱项，以及队员 Runtime 环境中的用户级和项目级原生 Skills。同名的不同来源分别显示。

旧 Skill Library 的导入、启停和 Runtime 交付组已退出当前设置入口。新配置按队员保存，不再向项目创建旧式 Skill 投影。来源可见只说明文件被发现，不代表 Runtime 已加载或模型已经读取。

## 8. MCP 支持

在设置的 MCP 页面中可以维护 External MCP，并分配给需要使用它的队员。

大多数 Runtime 会在保留原生 MCP 配置的基础上，为当前 Run 兼容追加 Rovai 分配的 MCP。Antigravity 当前只保留 Runtime 原生 MCP，不追加 Rovai External MCP。

添加 MCP 前应确认：

- 启动命令或服务地址可信；
- 凭据通过安全方式提供；
- 工具暴露范围与当前任务匹配；
- 不把密钥直接写入公开仓库。

## 9. 查看运行状态

每名正在行动的队员都有独立 Run。

在会话区和运行监控中可以查看：

- 当前状态与执行阶段；
- 工具调用和中间结果；
- 权限请求；
- 完成、失败或未完成原因；
- token 用量；
- 缓存读取、写入与命中情况；
- Runtime 和模型覆盖情况。

只有 Runtime 提供可靠结构化数据时，Rovai 才会显示对应 token 或缓存结论。没有证据的字段会保持未知。

## 10. 留下有用的团队记忆

团队记忆不等于保存全部聊天记录。

从“设置 → 记忆”查看和审核记忆。有待审核项时，也可以点击设置旁带数量的记忆快捷入口。

更值得留下的是：

- 为什么选择当前方案；
- 哪些分歧还没有解决；
- 哪些风险已经接受；
- 执行结果与失败原因；
- 下次不必再走的弯路；
- 哪位队员更适合处理某类问题。

在结束一段重要任务前，可以请记录型队员整理：

```text
请记录这次任务最终选择、主要理由、未解决问题、执行结果，
以及下一次继续时最先需要确认的事情。
```

这样下一次回到对话时，队伍可以从已有判断继续，而不是重新解释所有背景。

## 建议的第一次任务

第一次使用时，先选择一个范围小、结果容易判断的真实任务，例如：

- 阅读一个模块并解释它的职责；
- 对一份方案进行双人追问；
- 让队伍讨论一个产品取舍；
- 修改一处小功能并查看完整 Run；
- 总结一次任务并形成团队记忆。

先观察队员之间的分工，再逐步调整角色、模型、权限和 Skill，比一开始组建过大的队伍更容易找到适合自己的协作方式。
