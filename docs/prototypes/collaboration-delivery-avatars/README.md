# 协作投递 · 单行头像设计稿

交互原型，不是已交付功能或新的生产合同。打开本目录的 `index.html` 即可查看；所有消息、运行状态与多人名单都是演示数据，不连接 Core、Runtime 或真实 Camp。三个当前队员的头像来自本机已有图片，其余使用内置头像或字形回退。

## 设计范围

- 直接复用生产 `AppHeader`、`CampWorkspace`、执行台、执行浮层、过程详情和主题 CSS。
- 仅在原型构建时替换协作投递的筛选与收件人行，不修改生产源文件。
- 以“本次执行发给谁”为展示口径；同一队员无论投递几次，只出现一次，保持首次出现的顺序。
- 保留“协作投递”标签；行内只显示 24px 头像，焦点区域为 28px，头像之间不重叠。
- 根据剩余宽度计算可见人数，为 `+N` 预留完整位置；不换行、不横向滚动、不裁掉半个头像。
- 悬停或键盘聚焦头像显示姓名；`+N` 可以打开其余队员名单，支持键盘和 Escape。
- 没有协作投递时隐藏整行，不保留空白标题。
- 支持两种承载位置、两套生产主题，以及 0 / 1 / 2 / 16 位对象的演示场景。

## Skill 对设计的影响

UI-UX-PRO-MAX 的 `Chip Collection Reflow` 指引支持可操作的 `+N` 溢出入口；本稿遵循用户的单行要求，不采用换行。Accessibility / Icon Context 指引用于姓名提示、键盘焦点和可访问名称。React Effects 指引用于清理尺寸观察器。

Impeccable 的 Distill 路径只用于移除重复姓名与冗余头像，保留现有界面和全部身份信息。未替换全局设计系统，未修改产品文档，也未启用插件或 hooks。

## 重新构建

在仓库根目录运行：

```sh
node docs/prototypes/collaboration-delivery-avatars/build.mjs
```

构建脚本读取当前生产代码，并在内存中替换两处原型接缝。它还读取已明确定位的三个本机头像图标；其他机器如无这些图片，应先调整构建脚本的头像来源。生成的 `index.html` 已内嵌样式、代码和图片，浏览时不再读取本机数据目录。
