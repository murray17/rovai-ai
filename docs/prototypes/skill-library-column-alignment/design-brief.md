# Skill 列表四列表头对齐设计简报

## 问题

生产页面把三列表头放在搜索工具栏右侧，把每一行的三个控件放在列表容器和卡片内层。
两处虽然都使用 `118px / 48px / 30px` 与 `8px` 间距，却不共享同一个外层参照：列表先有
`7px` 内边距，卡片内容再有 `11px` 内边距。结果是行控件整体比表头向左收进 `18px`，
宽度越大越像是三列分别偏位。除此之外，主信息列没有表头，用户无法从列表首行确认左侧
名称与简介和右侧三个控制列属于同一个列模型。

## 方案

1. 搜索框保持原位并占满可用宽度，不改变搜索交互。
2. 将“Skill / 生效范围 / 状态 / 查看”移入 `.skill-card-grid`，作为列表内的轻量说明行。
   参考 MCP Library，`34px` 身份标记轨道保留为空白结构位，`Skill` 放在主信息轨道。
3. 表头复用行内容的两层 Grid：外层 `34px / 1fr / 212px`，内层
   `118px / 48px / 30px`。列宽、间距和左右内边距只定义一次。
4. 表头沿用 MCP Library 的 `32px` 高度与轻量标签排版，没有单独卡片、边框或阴影；
   它属于列表结构，不成为新的信息层级。
5. 小于 `820px` 时隐藏表头，并沿用生产页面的两行卡片布局：名称与简介在第一行，三个
   控件在第二行。DOM 与键盘顺序不变。

## 交互边界

- 生效范围仍是可连续多选的菜单，选择一项后不自动关闭；`Esc` 关闭并把焦点还给触发按钮。
- 状态仍使用现有无文字 Switch；保存期间禁用当前行，不移动其他列。
- 查看仍使用现有 Chevron，原地展开详情；展开不会改变三列宽度。
- 表头仅作视觉说明并 `aria-hidden`；每个控件继续用自己的可访问名称表达 Skill 与当前状态。
- 搜索、空态、错误、禁用与详情内容均不改变现有产品语义。

## 为什么不用补偿边距

给工具栏添加 `18px` 右内边距可以暂时让当前尺寸对齐，但表头与行仍由两套容器独立计算。
后续只要列表内边距、卡片密度或窄窗断点变化，偏差就会复发。共同轨道把对齐关系写进结构，
而不是写成一次性的光学校正。

## 生产实现映射

- `SkillSettings.tsx`：把 `.skill-library-legend` 从 `.skill-library-toolbar` 移入
  `.skill-card-grid`，并增加与 `.skill-card-primary` 同轨的外层包装；身份标记列留空，主信息列
  显示 `Skill`。
- `styles.css`：工具栏改为单列；新增列表内表头的外层 Grid；内层继续复用
  `.skill-card-controls` 的列定义或抽取同一组自定义属性。
- 响应式：现有 `820px` 断点继续负责隐藏表头和把控件移到第二行。

## 附件交付边界

Camp 会把附件复制到独立的受管目录，因此交互稿不能依赖仓库相对路径。`index.html` 必须由
`bundle.mjs` 内嵌生产 `styles.css` 后再发布；验收时从只包含这一份 HTML 的临时目录打开，
并确认外部样式表数量为 `0`、内嵌生产样式存在且页面仍按双列 App Shell 渲染。

本简报只拥有 Renderer 交互与布局参考，不改变 Skill Library、投递、启停、来源或删除合同。
