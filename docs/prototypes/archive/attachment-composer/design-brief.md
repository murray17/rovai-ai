# Camp Composer 附件输入设计简报

## 设计目标

让截图和本地文件像文字输入一样自然进入一条 Camp 消息，同时保持 Rovai-ai 已有的消息冻结、AgentRun 上下文投影和安全边界。

## 输入模型

文字与附件属于同一份消息草稿。附件不作为本地路径文本插入输入框，而是进入独立附件队列；发送后形成不可变的消息附件，并向 AgentRun 提供受控的只读投影。

## 输入入口

当前设计不提供回形针、“添加附件”按钮或可见文件选择器。用户通过两条路径添加附件：

1. 在输入框中粘贴截图或剪贴板文件；
2. 从 Finder 拖放文件到 Camp 工作区。

纯文本粘贴保持原有行为。

## 输入框内布局

- 附件队列嵌入文本输入区域内部左下角。
- 附件从左到右排列，超出宽度后在附件行内横向滚动。
- 图片使用固定 `1:1` 的小型正方形缩略块；文档使用横向长方形卡片。
- 图片与文档保持等高：常规窗口 `52px`，窄窗口 `50px`。
- 图片点击或键盘激活后打开大图预览。
- 每个附件提供可聚焦的移除操作和包含文件名的无障碍名称。

## 会话区布局

会话历史不复用输入框内的紧凑附件布局：

- 附件位于消息正文之后；
- 多个附件纵向排列；
- 图片展示为 `160×160px` 的正方形圆角缩略图，点击后按原始比例放大；
- 文档展示为独立横向文件卡片；
- 展示安全文件名、类型、大小和冻结状态，不展示绝对路径。

## 状态

- `ready`：可以发送。
- `preparing`：本地复制、读取、哈希或安全检查进行中，暂时阻止发送。
- `error`：附件原位显示错误，移除或重新添加后恢复发送。
- `dragging`：Composer 显示明确的放置反馈，但不遮挡整个工作区。

文字或 Ready 附件任意一个存在即可发送；存在 `preparing` 或 `error` 附件时不允许部分发送。

## 安全与隐私

- 不显示用户本机绝对路径。
- 发送后附件身份冻结，原文件后续变化不改写历史消息。
- Agent 只读取受控投影，不直接访问用户粘贴或拖入时的原始路径字符串。
- 错误必须在附件卡片原位可见，Toast 只作为补充反馈。
