# Rovai-ai Camp Composer 附件设计稿

这是 Camp Composer 支持**粘贴附件**与**拖放附件**的交互式 HTML 设计稿，视觉与布局沿用 Arctic Dawn V3。

## 文件

- `rovai-attachment-composer-prototype.html`：可直接用浏览器打开的交互式设计稿。
- `design-brief.md`：当前设计语义、交互规则与实现边界。

## 本轮改动点

### 1. 输入框内附件布局

- 不提供回形针、“添加附件”按钮或其他显式文件选择入口。
- 附件只通过以下方式进入草稿：
  - 在输入框内粘贴截图或剪贴板文件；
  - 从 Finder 拖放文件到 Camp 工作区。
- 待发送附件位于**输入框内部左下角**，从左到右排列。
- 图片附件使用较小的正方形缩略块。
- 文档、代码、PDF、表格等使用横向长方形文件卡片。
- 图片卡片与文档卡片保持等高：
  - 常规窗口高度为 `52px`；
  - 窄窗口高度为 `50px`。
- 图片卡片始终保持 `1:1` 正方形，使用裁切缩略图，并支持点击或键盘激活后放大预览。
- 附件过多时只在输入框内部附件行横向滚动，不扩张主页面宽度。

### 2. 会话区附件布局

输入框里的紧凑附件样式不会复用到会话历史。

- 附件显示在用户消息正文下方。
- 多个附件按从上到下的顺序纵向排列。
- 图片使用 `160×160px` 的正方形圆角缩略图，点击可打开按原始比例展示的大图。
- 文档使用独立横向文件卡片，展示类型、文件名、大小和冻结状态。
- 会话区不把附件固定在消息左下角，优先保证阅读流清晰。

### 3. 状态与发送规则

- `ready`：附件已准备，可以随消息发送。
- `preparing`：正在创建受管只读副本；允许继续编辑文字，但暂时不能发送。
- `error`：在附件卡片原位显示错误；移除失败附件后才能发送。
- 文字为空但存在 Ready 附件时允许发送。
- 发送后附件作为该消息的冻结上下文，不显示用户本机绝对路径。

### 4. 拖放与粘贴

- 文件拖入 Camp 时，视觉反馈收敛到 Composer，不用全屏遮罩覆盖会话区、Inspector 或审批区。
- 粘贴内容包含真实文件时，将文件加入附件队列，并避免同时插入浏览器派生的图片 URL 或 HTML 文本。
- 纯文本粘贴保持普通输入行为。

## 查看方式

直接双击或用浏览器打开：

```text
rovai-attachment-composer-prototype.html
```

设计稿顶部的状态切换器只用于评审 `empty / ready / dragging / preparing / error`，不属于生产界面。

## 当前尚未确定的产品合同

- 支持的文件类型与单文件大小限制；
- 单条消息的附件数量及总大小限制；
- 是否支持目录拖放；
- AgentRun 运行中是否允许预先准备下一条消息的附件；
- 受管附件副本的保存、清理与历史消息生命周期。
