# 执行区浅色背景候选

用户认为原生产混色偏绿、直接复用视图按钮选中态又偏深，因此先出 HTML 配色稿供选择。
2026-08-31 用户选定 A「瓷白」，生产实现通过独立的 `--execution-running-surface` 落地，
不修改视图按钮的选中态颜色。B、C 与上一版保留为评审对照，不是额外的生产主题。

## 查看

[打开设计稿](index.html)。这是自包含 HTML，不依赖服务器、外部字体、图片或第三方脚本，下载后可离线打开。

- A 瓷白：日间 `#fafafa`，夜间 `#1b2024`。最轻，优先推荐给希望尽量接近会话白底的选择。
- B 浅雾灰：日间 `#f3f4f5`，夜间 `#20262b`。偏中性，背景层次稍明显。
- C 淡钢蓝：日间 `#f3f7fb`，夜间 `#1d272e`。保留很轻的 Steel 色相。
- 上一版对照：日间 `#e9eef3`，夜间 `#22303a`，只作对照，不是新候选。

同一个文件支持候选切换、日夜主题、底部执行台／执行浮层、并排对比，以及上一版前后切换。
URL 查询参数可保存 `variant`、`theme`、`placement`、`view`，只接受设计稿内的已知值。

## 不变的边界

- 只改变运行中 Run 与含收起／停止操作的栏，两块始终同色。
- 历史 Run、队员入口、外壳、空白与会话区同色。
- 状态文字、图标、边框、Evidence 与按钮选中态不随方案改变。
- 场景为现有会话工作区的局部示意，不新增产品入口，不定义新的执行交互。
- 只有场景外的设计稿控制器可操作；场景内按钮和运行信息都是静态示例，不启动模型、不改变 App 或真实 Run。
- A 已被选定；生产实现、验收和主题合同分别维护在对应真源，HTML 仍只承担静态设计对照。

## UI-UX-PRO-MAX 应用

使用本地 UI-UX-PRO-MAX 做两个定向查询，而不是重建产品设计系统：

1. `monochrome minimalism --domain style`：匹配 `Minimalism & Swiss Style`，采用适用于专业工具的低色量、
   内容优先和清楚的文字层级。没有照搬查询结果的纯黑白品牌、零圆角或间距。
2. `color contrast --domain ux`：匹配 `Color Contrast` 与 `Color Only`，要求普通文字至少 4.5:1，
   保留执行状态文字、形状和位置，不把底色当成唯一状态信号。

具体色值是依据用户反馈和现有主题手工推导的候选，不冒充资料库给出的成品色板。
Impeccable 仅作为局部配色与既有视觉体系检查，不引入新的视觉世界。
