# 飞书聊天 Bot PRD

## 1. 文档定位与开发约束

- 版本：PRD v3，2026-10-20。相对 v1、v2 的变更见第 12 节末尾。
- 本文为本地实施输入，不代表功能已实现、测试通过或获得平台准入。未授权暂存、提交、推送。
- 需求范围以本文为准；此前的本地调研草案仅保留讨论背景，不得从中恢复已撤回的要求。
- 本文不直接覆盖仓库当前 Architecture、Contracts、UI 或版本状态；实施时按仓库规则同步必要合同。
- 未列入范围的功能不添加。实现必须改变产品行为时，先说明差异并取得用户同意；不得以"安全""扩展性""体验优化"为由自行加审批、角色系统或新功能。
- 内部模块与存储命名、模型 API 适配、检索方式、资源上限的具体数值，由实施选择最简单的方案，不借此扩大产品范围。

## 2. 产品目标

把飞书 Bot 分成两种模式：只给 Owner 用的**工作 Bot**（现有功能，不改动），以及所有人都能用的**聊天 Bot**（本次新增）。聊天 Bot 负责回答资料问题、传话、代问和反馈结果，不具备任何本地工作能力。

聊天 Bot 的使用者能够：

1. 与 Bot 正常聊天。
2. 根据 Owner 指定的共享资料文件夹提问。
3. 让 Bot 把明确的内容转给指定的人。
4. 让 Bot 向某人询问一次，并收到对方答复的汇总。
5. 在资料不足或需要最新情况时，由 Bot 询问 Owner，再把答复转回。

成功标准：沟通闭环准确、资料引用可辨认、异常结果诚实。

## 3. Bot 模式与角色

### 3.1 "仅 Owner 可交互"开关决定 Bot 模式

| 开关 | 模式 | 谁能使用 | 能力 |
| --- | --- | --- | --- |
| 打开（默认） | 工作 Bot | 仅 Owner | 与现在完全一致，本功能不做任何改动 |
| 关闭 | 聊天 Bot | Owner、同事、已接入的外部联系人 | 只有第 6 节的聊天能力；Owner 本人也不能让它做本地工作 |

- 一个 Bot 同一时间只能是一种模式；切换只影响当前 Bot，不影响其他 Bot。
- 同时需要两种能力时，在飞书后台创建两个应用，并在软件中分别发布：一个保持打开，作为工作 Bot；一个关闭，作为聊天 Bot。
- 关闭开关时提示：该 Bot 将不再处理 Owner 的本地工作请求；如需继续使用工作能力，请保留另一个工作 Bot。
- 旧 Bot 升级后保持打开。发布后可随时切换。
- 关闭开关前必须已配置聊天模型；未配置时提示先配置，不允许关闭。
- 切换为聊天 Bot 后，不使用、不公开该 Bot 原有的工作会话和历史；聊天使用独立上下文，不再发送运行状态卡。
- 切换回工作 Bot 后，非 Owner 消息不处理、不回复；尚未发出的聊天消息取消；未结束的沟通事项暂停。再次切换为聊天 Bot 时，暂停的事项继续等待回复，已取消的消息不补发。

### 3.2 角色

- **Owner**：发布该 Bot 的已验证所有者，不因有人先发消息而改变。在聊天 Bot 中与其他人使用相同的聊天能力，另外还是"向负责人确认"的对象，并可结束任意沟通事项。
- **请求者**：发起提问、转发或代问的人，可以是 Owner、同事或已接入的外部联系人。
- **被询问者/接收人**：被指定接收消息或提供信息的人。

## 4. 配置

集中在现有 Bot 设置中，不新增独立管理台：

| 配置 | 规则 |
| --- | --- |
| 仅 Owner 可交互 | 见 3.1 |
| 聊天模型 | Provider、模型、凭据；适配器支持自定义地址时才显示地址。与工作 Runtime 分开 |
| 共享资料文件夹 | 可选；每个 Bot 最多绑定一个 |

### 4.1 共享资料文件夹

- 用户在软件内把一个已有文件夹设为"共享资料文件夹"，无需复制或上传。
- 再选择使用它的聊天 Bot；多个 Bot 可共用同一文件夹，未绑定的 Bot 不能读取。
- 设置时提示一句：文件夹内的资料将用于回答该 Bot 使用者的问题，相关片段会发给所选模型服务商处理。
- 文件夹只应放允许共享的资料，不做逐人、逐文件权限。"只答相关内容"是回答规则，不能保证混放进来的秘密不会被多次提问拼出来。
- 可更换或解绑；文件夹不可用时只暂停资料问答，其他功能不受影响。

### 4.2 飞书后台前提（由用户在飞书开放平台配置）

- 应用的可用范围包含需要交互的同事。
- 聊天 Bot 需要通讯录读取应用权限，用于按姓名查找同事；工作 Bot 不申请该权限。发布聊天 Bot 时随 Bot 权限一起申请。
- 已发布 Bot 从工作 Bot 切换为聊天 Bot 时，需要补加该权限并重新发布；权限生效前，按姓名找人暂不可用，其他功能正常。
- 能搜到哪些同事取决于飞书后台为该 Bot 配置的通讯录范围。需要管理员审批时，审批通过前按姓名找人暂不可用。
- 切回工作 Bot 后不再使用该权限；首期不主动撤销已申请的权限，避免反复发布审批。
- 外部联系人：应用需满足飞书对外共享条件；外部用户必须先主动与 Bot 建立单聊。

## 5. 对话与回复位置

- 在群里提问就回复原群，在私聊提问就回复原私聊；请求者提到"保密"也不改变回复位置。
- 群内只处理 @ Bot 的消息。Bot 在群里提问时提示对方"回复这条消息并 @ 我"。
- 私聊和群聊的上下文分开，不混入其他人的私聊。
- 回复位置在受理请求时确定，模型不能更改。原位置失效时不改投其他地方；能联系到请求者就告知，否则只在本地记录结果。

## 6. 核心功能

### F1. 普通聊天与资料问答

1. 一般交流直接回复；不能把一般推测说成项目事实。
2. 涉及资料的问题，读取共享文件夹中的相关内容；资料足够回答时直接答复，不先问 Owner。
3. 只回答问题涉及的内容，不附带其他项目、人员或无关段落，不发送整份文件、目录清单、附件、链接或本地路径。
4. 注明出处，例如"根据《项目进展记录》中 10 月 16 日的记录……"。内容中没有日期就注明"未标注日期"，不用文件修改时间代替业务日期。
5. 找不到依据、内容矛盾或无法读取时如实说明，不编造；需要核实的转为 F2。普通闲聊不转问 Owner。
6. 问题含糊时先澄清，不列出全部资料或项目让对方挑。

### F2. 向 Owner 确认

- 出现以下任一情况时，Bot 私聊 Owner 提问：资料不足、资料矛盾、资料无法读取，或请求者明确要求最新、实时的情况。即使资料当天有更新，后一种情况也照样询问。
- 先回复请求者一句"我向负责人确认一下"。
- Owner 的答复按 F5 关联，整理后发回原请求会话，保留事实、缺失项和不确定项。
- Owner 未回复时保持等待，不催问，也不把旧资料说成"负责人已确认"。
- Owner 的答复只用于这一次提问，不写回资料，也不用于回答其他人。

### F3. 转发

- 任何使用者都可以要求 Bot 把内容转给 Owner 或其他指定的人。接收人和内容都明确，且满足 F5 的可联系条件时直接发送，不再二次确认。
- 转发时注明"受 A 委托转告"，不冒充 A 或 Owner。
- 只转发明确提供的内容，不附带聊天历史。
- 发送成功即完成，不自动把对方的回复转回来；需要带回结果时按 F4 处理。

### F4. 代问与回传

- 任何使用者（包括 Owner）都可以发起代问。Bot 向指定的人询问一次，并说明受谁委托、答复会发回哪里（哪个群或私聊）。
- 对方回复"我查一下""稍后回复"时继续等待，不算完成。
- 收到实质答复后，向请求者发送阶段汇报；处理期间同时到达的多条回复合并处理。之后有补充时，只汇报新增或更正的部分。
- 对照原问题标注"截至目前未说明"的项；不猜测，不追问，不催促。
- 不设固定静默时长，也不设自动过期。
- 结束条件只有两种：Owner 结束（可以结束任意事项）；被询问者明确拒绝（同时如实告知请求者）。事项结束后，迟到的回复不再回传，事项也不重新打开。
- 被询问者提出的工作要求不执行，可以如实带回给请求者。

### F5. 找人与答复关联

**找人**

- 可以找到以下几类人：Owner；消息中 @ 的人；聊天 Bot 通讯录权限生效后，在权限范围内按姓名搜索到的同事；已主动与 Bot 对话过的外部联系人。
- 每次找人时实时查询，不保存或同步整份通讯录。外部联系人不能按姓名搜索。
- 同名多人时先问请求者是哪一位；找不到时说明情况，请对方 @ 此人或提供更准确的信息，不猜测。
- 外部联系人必须先和 Bot 建立单聊，Bot 才能私聊发送。未建立时，提示对方先建立单聊，不假称已经发出。
- 不展示或返回通讯录列表。

**答复关联**（对 Owner 和其他人一视同仁）

- 新请求优先：例如“帮我转告李四”“查一下项目 A”这类新的转发、代问、资料查询或其他请求，不能作为待回复事项的答复。
- 对方引用回复了 Bot 的询问消息：关联到该事项。
- 对方没有引用，且不是新请求，同时当前只有一件事项在等他回复：直接关联。
- 有多件事项在等他回复：请他引用对应的询问，或说明是哪一件，不猜测。
- 没有事项在等他回复：按普通聊天处理。
- 回传时只整理与该事项相关的内容。对方顺带问 Bot 的其他问题，按普通聊天单独回复，不转给请求者。

## 7. 资料读取规则

- 支持 UTF-8 编码的 Markdown（`.md`）和 TXT（`.txt`）文件，包括真实子文件夹中的文件；不跟随符号链接或 Windows junction，不读取文件夹以外的位置。
- 隐藏文件、不支持的格式、读取失败或过大的文件不参与问答；在设置中显示简短的状态说明。
- 文件数量和大小使用简单的固定上限，具体数值写在实施计划中。
- 每次回答资料问题都重新读取当前文件夹，因此文件的新增、修改和删除会自动生效。
- 之前的资料答复不作为回答新问题的事实依据。
- 解绑或更换文件夹后不再读取原文件夹；尚未发出的资料答复直接丢弃。已经发出的消息无法撤回。
- 文档内容只作为资料，不能让 Bot 修改权限、联系他人或执行任何操作。

## 8. 聊天模型与体验

- 不启动本地编程工作流程。
- 模型负责理解和生成文字，并提出以下动作：回复当前会话、找人、转发、代问、向 Owner 确认、检索资料、结束事项。程序校验身份、目标和范围后再执行。
- 不提供文件写入、终端、任意网络请求、MCP/Skills、工作 Agent、跨会话历史或全局记忆。
- 等待别人回复期间不占用模型调用。
- 模型调用失败时给出简短提示，不回退到工作 Agent。
- 对外只发送普通文字，不发送运行状态卡、执行过程、控制台入口或本地路径。
- 对请求频率、并发数、输出长度和超时设置简单上限；这些上限不用来判断对方是否已回复完毕。
- 不承诺具体响应时间；验收时记录实际耗时。

## 9. 异常处理

| 情况 | 产品行为 |
| --- | --- |
| 没有资料文件夹或无法读取 | 其他功能正常；资料问题说明无法查询，必要时转问 Owner |
| 模型调用失败 | 发送简短失败提示；已受理的事项保留 |
| 电脑休眠、App 退出、断网 | 不承诺在线；已保存的事项在恢复后继续；离线期间的消息能否补收取决于飞书 |
| 收到重复事件 | 不重复转发或汇报 |
| 发送失败 | 告诉请求者发送失败，不报成功 |
| 无法确认是否发出 | 告诉请求者"暂时无法确认是否发出，请勿重复发送"；不盲目重发 |
| 原群不可达或 Bot 被移出群 | 停止投递，不改投其他地方；能联系到请求者就告知 |
| 目标不在可用范围，或外部联系人未建立单聊 | 明确说明，不假称已发送 |
| 切换回工作 Bot | 见 3.1 |
| 模型生成回复期间收到新消息 | 新消息不丢失，留到下一轮处理；旧的生成结果不覆盖新事实 |

## 10. 不做清单（唯一清单，其他文档引用此处）

- 对工作 Bot 做任何改动；聊天 Bot 联系工作 Agent 或查询其进度。
- 本地文件修改、代码执行、终端、任意网络请求、MCP/Skills。
- 转发确认卡、通用审批、逐文件或逐人权限、秘密分级、保密模式、额外安全审核模型、全量聊天审计副本。
- 用固定静默时间判断对方回复完毕；默认过期；自动追问或催办；自动生成日报或推进项目。
- 图片、语音、附件、PDF、Office、OCR；网页或云盘同步；批量群发；向量知识库。
- 双向聊天镜像、递归代问、通讯录列表展示或同步。
- 写入 Owner 全局记忆，或开放历史检索。
- 多 Bot 编排、所有权转移、切换登录账号的处理、托管 Web 端设置、Lark/钉钉改造、独立服务端部署。

## 11. 验收清单与最小测试原则

| 编号 | 验收点 | 必须得到的结果 |
| --- | --- | --- |
| A01 | 模式开关 | 一个 Bot 只能是一种模式，切换只影响当前 Bot；打开时行为与现在一致，非 Owner 无回复；关闭时所有人（包括 Owner）只有聊天能力；未配置模型时不能关闭；切换回工作 Bot 后的行为符合 3.1 |
| A02 | 资料问答 | 只答相关内容并注明出处，不输出全文、路径或目录；查不到时不编造；更新、删除、解绑立即生效；目录外文件、链接跳转、文档中的指令都无效 |
| A03 | 向 Owner 确认 | 资料当天更新过也照样询问 Owner；Owner 的答复准确发回 |
| A04 | 找人 | 聊天 Bot 通讯录权限生效后可按姓名找同事；权限未生效或不在范围内时其他功能正常；@、同名澄清、找不到、外部联系人未建联各自结果正确 |
| A05 | 转发 | 直接发送；发送成功、失败、无法确认三种情况的反馈正确 |
| A06 | 代问 | A→B→A 闭环成立，群里发起的回到原群；对方说"稍后回复"不算完成；阶段汇报与补充汇报不重复 |
| A07 | 答复关联 | 新请求不被误关联；引用回复、只有一件事项时直接关联、多件事项时澄清，都正确；只回传相关内容；事项结束后迟到的回复不重开 |
| A08 | 重复与恢复 | 重复事件不导致重复发送；重启后等待中的事项和待发消息继续 |
| A09 | 外部展示 | 不出现运行卡、控制台入口或本地路径 |
| A10 | 真实平台 | 用测试 Bot 验证同事私聊、聊天 Bot 通讯录应用权限与搜索范围、模式切换后的权限生效、外部联系人首次建联、群内 @、引用回复 |

上表是产品验收点，不要求每一行单独建测试：

- 规则类逻辑在单元层用表驱动测试覆盖。
- 持久化和重启只在负责该机制的那一层测试，调用方只验证接通。
- 越界读取、文档注入各保留一个代表性反例，不堆砌同义的恶意提示。
- 真实飞书和模型调用只做少量 Smoke 测试，执行前需另行获得授权。
- 未执行、被平台阻塞或失败的项如实记录，模拟通过不等于真实验收通过。

## 12. 实施顺序与变更控制

### 实施顺序

0. **平台确认**：用测试 Bot 手动验证 A10 列出的平台能力（需授权），包括聊天 Bot 通讯录应用权限、发布/切换后的生效情况和搜索范围。
1. **模式与聊天基础**：开关、聊天模型配置、独立上下文、文字回复、不发运行卡。
2. **资料问答**：文件夹指定与绑定、只读检索、注明出处。
3. **通信闭环**：找人、转发、代问、向 Owner 确认、答复关联、阶段汇报与补充汇报。
4. **收口验证**。

### 防偏离规则

- 每个开发项必须对应本文某条编号规则；无法对应时先说明必要性，再决定是否实现。
- 遇到不支持的情况给出明确结果，不以越权回退来"先让它能用"。
- 产品范围变化时升级本文版本、说明原因，并取得用户确认。

### v2 相对 v1 的变更

- 开关改为决定 Bot 模式：打开为工作 Bot，保持不变；关闭为聊天 Bot，Owner 本人也只有聊天能力。删除"Owner 通过工作入口发起沟通"的设计。
- 工作 Bot 不改动，因此不再默认触发模型上下文变更的二次确认。
- 新增通讯录搜索（限权限范围内的同事）。
- 答复关联放宽：只有一件事项时可以直接关联，并对 Owner 同样适用；回传时只包含相关内容。
- 资料更新规则简化为每次重新读取；去掉逐文件版本追踪和读前读后比对。
- 发送反馈改为成功、失败、无法确认三种。
- 事项结束只保留"Owner 结束"和"对方拒绝"两种。
- 不做清单合并为一份；切换登录账号、托管 Web 端设置、Lark/钉钉移出范围。

### v3 相对 v2 的变更

- 明确一个 Bot 只能是一种模式，切换只影响当前 Bot，并提示切换后不再处理本地工作。
- 聊天 Bot 随发布申请通讯录读取应用权限；工作 Bot 不申请。切换为聊天 Bot 需补权限并重新发布。
- 增加新请求优先规则，避免把新指令误作待回复事项的答复。
- 统一外部联系人必须先建立单聊。
- 修复乱码。
