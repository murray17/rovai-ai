# 每日 Trace 采集与分析核验

用户要求继续检查数据能否采集、分析内容是否到位，沿用已授权范围自主修正。此次复用 Core Trace 统计、离线报告、既有只读数据库测量接口与 CLI 模型调用，不修改普通用户字段、产品上下文或原任务。

## revision 1：修正与冻结范围

既有 Automation 实测使用空数据库，只证明准备、触发与登记链路可运行；不能证明非空数据覆盖。已从运行进程的明确 data-dir 找到来源，以 `open_read_only_measurement` 和原有 Trace export 只读事务导出最近 7 个完整自然日，未启动 Core、迁移、恢复或重跑任务。安装版尚无 `app trace`，因此这次只读测量不冒充已部署的日常 CLI 链路。

两个最小失败测试复现跨日交接口径与采样总体问题：旧 `openCountAsOf` 只有当日群组，而等待原因包含旧积压；旧样本会纳入被指标排除的 Core 回放及非 A2A 完成投递。真实记录还显示 22 条 `unsettled` 工具终态未在摘要表中展示。按 [Execution Evaluation v12](../../contracts/execution-evaluation-v12.md) 修正，不改变原始成功／失败数量、分母或既有数据。

分析输入升级为明确的健康分析策略，提供分类有界样本、采样分母、未判定终态与覆盖说明。模型不评价需求或协作质量、不推测不可见工具错误原因。prepared 提前核验摘要，登记保留代码派生的指标引用值。工具失败率、记忆两计数和曲线数量不增加。

## 验证与预算

验证跨日积压和当日群组分离、样本与指标总体相符、全部终态可见、输入篡改被拒绝、旧报告不改写、零分母／不可用及缺日断线。使用同一份真实导出重新生成 7 日报告，独立复算数量与分母，核对每个样本引用。

冻结代码、7 份来源摘要、分析输入和 CLI 模型配置后，对最新完整自然日运行一次真实 gpt-5.6-sol / medium 分析，模型不带工具，最多 240 秒。记录原始输出、用量、身份和引用验证；不以合成数据代替实测。只有明确的结构／运输故障修正后才允许另存一次尝试，不能为了好看的结论反复抽样。实际结果另存结果文档，不覆盖此计划。

## 数据限制与成本

Run、交接状态与等待原因、当前 classifier 可观察工具状态可从既有记录获得；历史无当前 classifier 记录不能回填零调用。Core 工具错误码已有明确字段；Runtime 工具错误码需要逐 Runtime 的结构化证据适配，不能从失败状态猜测。模型 ID 可以沿用已存值，但历史空值无法可靠回填；未来覆盖取决于各 Runtime 的观测支持。

两项 Memory 计数按原约定留到记忆治理／成长阶段，需要逻辑调用去重与正式修订口径。逐 Run Rovai build 与完整 origin 如要永久可靠，需要未来 Run 的 provenance 设计和新增写入，不在本次默认加入。普通业务数据库没有增加字段；只在显式评测目录保存导出、报告和分析。

## revision 2：真实结构失败后的单次修正

revision 1 的实际模型调用已结束并保存：主要比例正确，但输出省略 `yesterday.` 路径前缀、引用未允许的根字段，并把报告 ID 当成样本 ID，登记按规则拒绝。模型还将稀疏状态表中未出现的已知零值误读成缺数据。保留此次报告、原始输出、失败登记与调用用量。

按 [Execution Evaluation v13](../../contracts/execution-evaluation-v13.md) 增加代码生成的有限输出引用 schema，并将可信终态分布中的标准零值明确提供给分析模型；未知总体仍不填零，不改变任何来源计数和失败率分母。不修改已失败的提交或放宽登记检查。

使用原来 7 份来源文件，在新目录生成策略 v3 的报告，冻结修正代码与模型配置后只追加一次最多 240 秒的真实分析调用。沿用 gpt-5.6-sol / medium，不新增工具或原任务执行。独立复算数值并核对自然语言中的总体、数值与未知说明；本次结构修正不用于宣称运行质量改善。
