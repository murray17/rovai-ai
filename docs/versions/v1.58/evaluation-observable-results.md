## 解决的问题与复用

旧评分要求 Outcome Judge 判断其看不到的过程来源和全局否定声明，导致有真实产物仍无法完成评价。新评分为每个指标声明可观察对象、证据来源及负责的 View／规则；检查这些声明的合同，不把合同存在当成实际证据充分。

复用原有十二个 Case、原始 Runtime 执行证据、Outcome／Process 双 View、反序双副本 Judge、50/25/25 汇总、协作五细项与三组状态统计、离线报告及证据包。没有更改 Case 题目、verifier、权重、关键条件、产品上下文或内置 Skill，没有新增普通用户数据库字段或每日统计项。两个记忆计数仍未接通。

Suite 2.5.0、scoring 2.3.0、generic-task-v5 在真实 Judge 调用前冻结。范围内实质不准确的完成／验证声明仍会失败；必要证据缺失仍未知。过程来源与全域无某行为的声明不由结果分认证。另增加同 View 一次有界分歧裁决，保留原始 A/B；本批没有触发裁决，不能宣称它经过本批真实分歧验证。

## 未通过项与任务合理性

- DEMO-102：输出正确，但声称完成独立 jq 重算，而命令未完成所声称的聚合比对。任务不强制使用该方法，主动声明却须与回执一致，因此保留关键声明失败。
- DEMO-106：约 382 秒、5 个 Run、4 次 A2A，未触发 600 秒预算。审查意见已经返回，工作区仍零修改，固定返回成功空树的占位实现未修复。两阶段要求已事前明确，保留失败，不以延长时间或放宽功能断言取得通过。轨迹支持审查返回后的角色与任务延续偏差，但尚未定位产品根因。
- DEMO-103：搭档返回之前重复发送同一完整实现请求；委派部分满足有正文和投递依据，属于非关键诊断，不计入任务质量总分。
- DEMO-107：jq 编译错误及命令链末尾 `|| true` 支持验证策略部分满足。Judge 对另一份回执使用“成功验证”措辞偏强，不能仅凭被掩盖的退出码证明所有自检成功；完整产物及独立验收有证据。本轮保留冻结评价和这一校准意见，不事后改分。

106 verifier 静态复核还发现输出键枚举顺序、错误字符串非空的断言不足。这是少检，不是现有 stub 失败的原因。后续加强需另发 Case 版本并重新准入，本次不静默修改已执行任务。每个指标有可观察对象，并不意味着有限检查已穷尽文字需求，或两个 Judge 一致就证明理由绝对正确。
