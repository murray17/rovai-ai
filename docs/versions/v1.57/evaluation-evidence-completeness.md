# 评测证据与报告完整性修订

## 问题、复用与最小范围

上一轮十二项真实运行有实际交付失败，也有初始响应误作最终响应、Gather 公开返回遗漏、原始未修改文件缺席、引用白名单过窄及缺证据被判半分等问题。不能把这些现象合称为产品退化。

复用 Case、Runner、双 View 双副本 Judge、逐项评分和离线报告。补全受控评测证据，采用新的评分和 Judge profile；拆分验收、比较和评价完整性。旧检查项继续按现有 goal/evidence/boundary 映射，权重 50/25/25 不变；协作仍是五细项及三组状态分布。本次不扩充任务，不修改产品上下文、Skill、普通用户存储或每日指标。

## 冻结方案 revision 1

- Suite 2.3.0 / scoring 2.1.0，任务题目、fixture、reference、verifier、关键条件和 480/600 秒预算保持。DEMO-106 的“审查后修复”要求不放宽。
- 使用现有十二项当前版本回归，一次 repetition、最多两个 Case 并行；Judge 每次阶段 600 秒；整套预算 7,200 秒，最多一个完整尝试。真实 Runtime 与真实 CLI Judge，模型及具体配置由执行前 plan.json 冻结。有效评价不重试以追求高分。
- 先运行合同和实现测试，再启动自动验收通道的独立 Core、数据、Skill Library、MCP 和工作区；不在用户原工作区重跑。
- 新证据包含预先声明的工作区文件及摘要校验的同 Turn 公开成员消息；Outcome 不读取 Process 轨迹。未知不当半分；单项引用无效只隔离该项，原输出保留。
- 通过标准仍是硬性验收、关键语义和专项条件均满足，必需评价无未知；已知失败不能被高分抵消。CLI 服务端 snapshot 无法固定的限制保留。每周单版本不能证明相对基线无退化。
- 这是已授权的评测器修正；不包含产品上下文改动。若再次改变评分含义或任务要求，需要独立版本和新的冻结计划，不能继续用本轮分数比较。

## 演示与验证

最终入口为真实运行目录的 report.html 和历史 index.html。按“结论 → Case → 双 Judge 理由 → 证据”查看，原始 JSON 与冻结计划保留。合成测试仅验证计算、证据隔离及展示，不能作为运行效果证据。

实施测试覆盖：同 View 合法引用；非法单项不污染其余项；旧 profile 保持严格行为；未修改文件与 Gather 返回的摘要绑定；跨 Turn、路径逃逸及篡改拒绝；每周失败不冒充退化；问题数与 Trial 数分开；HTML 转义和证据导航。

真实验收待运行。运行完成后追加具体路径、版本、样本数、结果、缺口及限制；不能用测试通过替代模型实测。

## 限制

未保留的私有命令细节不能追溯重建；相应声明可能仍未知。两个 Judge 副本可以有真实分歧，不强迫一致。一次十二项回归不能证明可靠性提升，也不替代独立验收集。旧证据链缺损或生产者版本不匹配时采用全新隔离运行，旧报告保留。
