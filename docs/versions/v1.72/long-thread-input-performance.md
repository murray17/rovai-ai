# 长会话输入性能实施与验收

公共历史虚拟化，以及仅在复测仍有瓶颈时实施的大内容优化。复用现有执行协议、存储与读取接口。

Web Chrome 生产组件基线：20/200/1,000 条混合历史 × 静止／当前 Run／其他 Thread × 三轮，
每轮 80 次输入、按键间隔 100ms、执行事件间隔 32ms，由浏览器外固定时间轴注入。

因此本轮证据指向工作区／历史构建与布局，不将组件重新执行等同于 Markdown 重新解析。

原始结果与首轮校准 trace 保存在本次 Thread 的附件输出目录 `perf-baseline-web/`。
20 条 idle 首轮与一次短 Desktop 探针重叠，不用于性能比较；其余正式采样期间没有并行性能任务。

## 第二批：公共历史挂载

公共时间线在超过 100 个结构项后按视口与缓冲区调用行渲染，稳定行容器在阈值两侧保持同一 key 与 DOM。
消息附属产物合并进所属测量行；稳定历史数据可以继续缓存，焦点、展开入口及原生选区额外保留其所需行，
实际额外节点由 `data-retained-count` 与行标记单独计量，解除交互后释放。

新挂载行先合并高度测量，再交还阅读锚点；动态尺寸变化保留可见消息，跟随标志只在原本跟随时更新尾部。
用户向上滚动／键盘回看会先退出底部跟随，避免同时发生的高度变化覆盖其意图。
虚拟历史的显式定位先挂载目标并直接滚动；短会话保留可中断的平滑动画。搜索、来源、回复、选文、用户目录
与通知复用原读取／定位链路；已加载但离屏不触发额外 around。缓冲区与保留项不代替真实可见确认。

已完成的定向检查：

- 200／1,000 条普通长链在相同视口均挂载约 10 条；1,000 条混合内容冒烟挂载 5 条。
- 12→62→112→162→200 条分页锚点偏差小于 1px；跨过阈值时消息 DOM、原生选区与键盘焦点均保留。
- 异步图片增长、追加消息不移动旧阅读位置；跨消息选区、焦点、展开身份入口的行保留与解除后卸载通过。
  视口之外的缓冲／保留项没有进入可见来源确认。
- 完整回复定位覆盖动态分组、不同宽度、完整阅读、补读、reduced motion、短会话动画中断与迟到响应隔离。
- 38 个执行状态、六种视口及活动行移动时的 DOM／焦点复用通过；Composer 和复制／导出交互通过。
- 通用 Vitest 277 文件、3,286 pass / 2 skipped；Node 377 pass / 2 skipped；默认 Rust workspace、
  TypeScript、通用文档门禁及 Web 生产构建通过。正式三轮性能对照在固定源码后单独采样，不与构建／测试并行。

### 真实系统中文 IME

以 `e6883be0dc66e4978741d4743dda88cb0892711c` 生产组件构建的隔离可见 Electron 窗口，
使用系统当前拼音输入法、1,000 条历史与每 32ms 的 Run 局部增量，通过原生按键验证组合与发送。
观察到 4 次 `compositionstart/end`、27 次组合更新及成对输入事件；候选期间 Return 只提交当前拼音，
没有提前发送。最终将“字”候选提交后立即 Return，发送入口取得完整“你好中文字”，输入框随后清空。
原始事件在本 Thread 附件 `native-ime.jsonl`；这证明交互正确性，不替代真实系统呈现延迟的分位数测量。

另以可见窗口补采原生按键的 Event Timing：1440×827、DPR 2、Electron 43.1.1 / Chrome 150，
1,000 条普通长链、32ms Run 增量；每 100ms 一个原生按键、持键 1ms，三轮各 180 键（约 18s），
每轮输入并提交 30 次“测试”。540 个按键均有记录，90 次中文提交和每轮最终 60 字完整；这是新实现的单独验证，
没有原生输入前后对照，不与混合历史的 headless／隐藏窗口数据混算。

| 原生中文三轮 | p50 | p95 | p99 |
| --- | --- | --- | --- |
| 第一轮 | 48ms | 56ms | 56ms |
| 第二轮 | 48ms | 56ms | 64ms |
| 第三轮 | 56ms | 56ms | 64ms |

一次单独的 65ms 人工处理延迟以 152ms Event Timing 被观察到，用于确认采样涵盖等待与后续渲染；
该校准及持键 50ms 的试采均不计入上表。正式三轮事件到达前等待 p95 为约 26–27ms，处理函数 p99 均为 0.5ms。
原生 p95 **尚未达到**拟定门槛，剩余耗时在事件投递前及处理后显示路径；现有证据不足以归因到某个输入法或合成器。
下一步应在可见完整 App 补 Renderer／compositor 联合 trace，区分输入工具、OS 投递、组合输入与呈现节奏，
再决定具体调度改动。该指标也不包含操作系统候选浮层的像素绘制，不能称为真实物理按键到像素的完整延迟。
采集与分析入口为 [`benchmark-native-ime.mjs`](../../../scripts/benchmark-native-ime.mjs)，原始记录与分析为
附件 `perf-native-ime/events.jsonl`、`perf-native-ime/results.json`。
