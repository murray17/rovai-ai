# v0.27 伙伴身份六字段生产设计

## 权威与原型边界

生产界面继续遵守 [Arctic Dawn V3](../../ui/arctic-dawn.md)。用户提供的 HTML 原型只
用于确认字段名称、基础/高级分组和信息排列；其中的配色、组件形态、间距、文案遗留、
响应式规则和演示数据都不是生产合同。

## 六字段模型

| 字段 | 当前定义 | 默认区域 |
|---|---|---|
| 名称 | 伙伴的长期称呼 | 基础身份 |
| 团队角色 | 伙伴在团队中的主要贡献类型 | 基础身份 |
| 专业职责 | 伙伴长期负责什么，以及通常交付什么结果 | 基础身份 |
| 性格底色 | 伙伴稳定的表达方式、判断倾向和协作风格；以用户可自定义标签表达 | 基础身份 |
| 工作准则 | 伙伴长期遵循的具体工作方式、质量要求和协作边界 | 高级设置 |
| 成长课题 | 伙伴当前希望逐渐练习或改善的方向 | 高级设置 |

工作准则辅助说明：

> 可选。补充这位伙伴长期遵循的做事方式、质量标准和协作边界。保存后会用于之后
> 接收的新请求，不影响已提交或正在进行的任务，也不会重置现有对话。

成长课题辅助说明：

> 可选。伙伴会在长期协作中围绕这个方向调整；实际形成的长期偏好、约定或经验仍按
> 既有记忆合同沉淀。更换成长课题不会清除已经形成的伙伴记忆。

## 内置角色默认配置

| Canonical Profile | 名称 | 团队角色 | 性格底色 |
|---|---|---|---|
| `agent-luoke` | 小狐狸 | 游学者 | 好奇 · 灵活 · 勤勉 |
| `agent-muwa` | 小河狸 | 鉴定士 | 严谨 · 沉稳 · 公正 |
| `agent-mianzhi` | 咕咕 | 巡夜人 | 警觉 · 耐心 · 求真 |
| `agent-qilu` | 小兔 | 绘图师 | 敏锐 · 细腻 · 灵动 |

专业职责分别为：

- **小狐狸**：负责理解需求、调查项目、编写文档，并将明确的方案实现为可运行、
  可验证的代码变更。
- **小河狸**：负责文档、方案和代码评审，检查事实、结构、边界、风险与实现是否一致，
  并给出明确、可执行的评审结论。
- **咕咕**：负责设计和执行测试、复现问题、检查边界与失败路径，并通过可重复的结果
  确认功能是否真正可靠。
- **小兔**：负责 UI、UX、视觉设计和前端实现，把复杂功能组织成清晰、顺手、有一致性
  的界面体验。

四个角色的工作准则和成长课题默认均为空。

## 性格底色标签合同

性格底色持久化为有序字符串数组，而不是用分隔符拼接的单个文本字段。合同为：

- 每个 Profile 最多 6 个标签；空数组合法。
- 每个标签去除首尾空白并折叠连续空白后包含 1～16 个 Unicode scalar value。
- 换行和控制字符非法。
- 比较时忽略大小写去重，保留第一次输入的文字形式与用户顺序。
- Renderer 通过回车或中文/英文逗号提交一个标签，并允许单独移除；Core 仍执行最终
  归一化与验证，不能把 Renderer 行为当成持久化权威。

标签只描述稳定的表达、判断和协作倾向，不是能力评分、Memory、Team Role、Working
Principles 或自由段落。详情与列表可用间隔符投影标签，但分隔后的展示文本不是真源。

## 必填、空值与长度

只有名称必填；团队角色、专业职责、性格底色、工作准则和成长课题均可为空。新建
Profile 可以只填写名称，之后逐渐补全身份。可选文本持久化为空字符串，性格底色持久化
为空数组，不用 `null` 表达“未填写”。

| 字段 | 上限与规则 |
|---|---|
| 名称 | 1～80 个 Unicode scalar value；去除首尾空白；全局唯一 |
| 团队角色 | 0～120 个 Unicode scalar value；去除首尾空白并折叠连续空白；不允许换行 |
| 专业职责 | 0～300 个 Unicode scalar value；去除首尾空白 |
| 性格底色 | 见“性格底色标签合同” |
| 工作准则 | 0～300 个 Unicode scalar value；去除首尾空白 |
| 成长课题 | 0～300 个 Unicode scalar value；去除首尾空白 |

Core 按 Unicode scalar value 执行最终长度验证，Renderer 需要给出相同计数与越界反馈；
不能继续沿用 Rust UTF-8 byte length 或浏览器 UTF-16 code unit 作为另一套合同。

## 生效与会话边界

“之后接收的新请求”在领域合同中精确指：身份保存成功后新创建的 AgentRun。Core 在
AgentRun 创建时把当时的六字段身份冻结为 Member Identity Snapshot；已经创建、排队、
等待或执行中的 AgentRun 继续使用自己的旧快照，不能在启动或恢复时改读最新 Profile。

新 Camp 本身不预创建 Conversation 或 Native Session。某位伙伴首次成为实际执行目标时，
Core 才创建该伙伴在该 Camp 内的 Conversation；其首个 AgentRun 自然创建新的 Native
Session，并使用当时冻结的最新身份。

已有 Camp 中，同一伙伴后续 AgentRun 继续复用该 Conversation 已绑定且兼容的 Native
Session。身份编辑不构成 Session compatibility 变化，也不轮换 Session；Core 只通过
每个 AgentRun 动态上下文的个人信息区域 `MEMBER_IDENTITY` 投递该 Run 冻结的六字段
身份。它不是 Session 级缓存，不增加已投递身份摘要或游标；失败或恢复继续复用同一份
冻结 ContextManifest。

因此 Session Charter 只保留稳定的 Core 平台、上下文权威和协作合同，不再持有可编辑
成员身份。头像仍是 Renderer 呈现，不进入 Member Identity Snapshot，也不影响 Native
Session。

## 本人上下文与团队可见范围

个人信息区域 `MEMBER_IDENTITY` 是每个 AgentRun 的必需区域，只投递给该 Member 自己，
包含其完整六字段身份。它不进入 Camp 公共消息，也不能成为其他 Member 的 Profile
快照来源。

同 Camp 其他伙伴的 `COLLABORATION_STATE` 仅投影协作所需的名称、团队角色、专业职责
和既有可用状态；不投影性格底色、工作准则或成长课题。这样其他伙伴可以判断分工与
交接对象，但不会依据私人性格标签、行为准则或成长方向给对方贴标签或干预其调整。
内部稳定 routing identity 仍按既有合同携带，不作为新的用户身份字段展示。

## 高级设置交互

身份编辑每次打开时，高级设置默认展开。标题始终根据已保存或当前草稿值显示“未设置”、
“已设置 1/2 项”或“已设置 2/2 项”，不能仅靠展开状态暗示是否已有内容。

工作准则或成长课题校验失败时保持展开并聚焦首个错误。保存失败保留六字段草稿、标签
顺序和当前展开状态，允许直接修正重试；明确取消、关闭或按 Escape 离开则丢弃这次
未保存的身份草稿，不做自动保存。

## 已确认升级原则

旧 `role_title`、`persona_label`、`role_description` 和 `instructions` 不进入新字段的
语义迁移。Migration 不调用模型、不做关键词分类，也不把无法判定的描述塞入性格标签。

升级按 Profile 身份分两类处理：

- `agent-luoke`、`agent-muwa`、`agent-mianzhi`、`agent-qilu` 无条件写入本版本确认的
  名称、团队角色、专业职责、性格标签，并把工作准则和成长课题设为空；`avatarRef`
  切换到对应的新受控内置外观。
- 其他用户创建的 Profile 保留稳定 ID、名称、`avatarRef`、Runtime 配置、Presence、
  Capability、Member Order、Memory、Camp 关系和历史引用；团队角色、专业职责、
  性格标签、工作准则和成长课题初始化为空，不读取旧身份字段。

名称碰撞是唯一例外：如果自定义 Profile 已占用本次内置角色的规范名称，内置角色取得
规范名称，自定义 Profile 保留稳定 ID 并改名为“规范名称 · handle”（必要时追加序号）。
这只用于维持全局名称唯一性，不保留旧身份字段的语义。

Migration 不物理删除 AgentProfile，不清除 Runtime、Memory 或历史数据，也不把自建
Profile 变为 away/removed。旧身份字段退出当前合同后不保留 Renderer/Core 兼容读写壳。

本机四个 canonical Profile 当前引用的四组受管素材已经核对为目标外观；实施时把对应
`source.png` 和 `icon-192.png` 纳入应用内置资源，不能依赖用户机器上的 managed URI
或绝对路径。

内置素材不建立 `v1`/`v2` 并存或旧外观兼容分支。现有四个受控内置引用继续作为唯一
当前引用，直接替换其打包图片、图标和预设内容；旧 bust、glyph、portrait、旧角色文案
及仅服务旧外观的注册代码在无当前使用者后删除。四个 canonical Profile 继续指向这套
唯一当前内置素材。其他自建 Profile 保留既有 `avatarRef`：managed 自定义图片不变，
引用内置外观的 Profile 会随唯一内置素材一起显示新外观，不提供旧图回退。

## 独立管理边界

- 角色图片保持 `avatarRef` 与受控 rendition 体系。
- Agent 运行时、模型和原生权限继续通过独立原子配置保存。
- Memory 写入能力仍是独立 Capability/应用设置，不由身份字段授予或撤销。
- 已形成 Memory 保持独立生命周期；身份字段编辑不能隐式 revise、retire 或 forget。

成员管理页可以同时呈现这些设置，但不提供跨区域“一键全部保存”：

- 六个身份字段由一个版本化命令原子保存。
- 角色图片通过独立动作保存；图片素材落盘与 `avatarRef` 切换必须保持可恢复，失败不能
  改动六字段。
- Runtime、模型和原生权限继续使用独立 Runtime 保存动作。
- 长期记忆写入开关使用独立 Capability 保存动作，不再夹带在身份命令中。

一个区域保存失败不回滚已经明确成功的其他独立区域，也不能让未提交区域意外生效。
每个区域只显示自己的忙碌、成功、冲突和错误状态。

## 成长课题与 Memory

成长课题和其他五个身份字段一样，只进入该伙伴后续 AgentRun 动态上下文的个人信息
区域。保存、修改或清空成长课题本身不创建、修改、停用或删除任何 Memory，也不新增
后台任务、成长日志、进度评分或按 Run 自动写入机制。

伙伴仍可在实际协作中按既有 `memory.write` 合同沉淀真正形成的可复用 Preference、
Agreement 或 Lesson。该行为继续受当前 AgentRun、Memory Capability、应用级开关、
合法 Scope/Kind、Secret Filter、容量和每 Run 配额约束；成长课题不能绕过这些边界，
也不能要求伙伴为了产生 Memory 而编造进展。并非每个 AgentRun 或每个成长课题都必须
形成 Memory。
