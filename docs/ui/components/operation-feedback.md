# 操作反馈

Desktop 与 Web 的操作反馈按操作和结构化错误码选择文案。错误码与后端原文留在诊断里，界面使用当前语言。
未知错误说明用户刚执行的动作，并给出可行的恢复方式。已处理、已离队等确定结果用中性提示。
原生审批选项、公开的执行失败记录和诊断页面遵循各自的呈现合同。

优先在操作所在的行、卡片、弹窗或页面呈现反馈。打开会话等跨页面动作复用[通用操作提示](app-shell-navigation.md#通用操作提示)，
同一个提示的关闭或重试只影响该提示的来源。无局部落点的主动失败使用内容区错误条。
错误条显示操作名称、具体结果和关闭控件，需要时提供对应重试。只有总览读取失败提供「刷新状态」。
会话内容区为错误条保留空间，输入框获得焦点后错误条仍然可见。

## 会话操作

| 操作 | 结果与恢复 |
|---|---|
| 停止执行 | Core 明确拒绝且版本冲突时刷新当前会话，用更新的 Run 版本和新命令 ID 自动补发一次。仍冲突时提示「执行状态刚刚更新，请再点一次停止。」。整轮已在停止时，执行行呈现正在停止。执行已结束时应用权威回执。结果待核对时由原请求的恢复流程处理。 |
| 打开会话 | 目标未打开时保留当前页面，使用带「重试」的提示。超时带上目标名称。重试沿用同一目标，离开原访问后旧动作失效。已恢复的缓存阅读面可继续显示，重试读取权威投影。 |
| 更换默认队长 | 选定队员已经离开时，刷新会话名册并说明该队员已离开、队长未更换。 |
| 提交审批 | 已处理、已过期或执行停止时在审批卡片内显示结果，收起原生选项，仅提供「知道了」。刷新后原请求从快照移除，结果保留到用户确认。连接类失败保留原选项，并说明提交失败。 |

## 后台读取

会话被动刷新失败时隔 1、3、10 秒重试。耗尽后提示一次「会话暂时没有刷新，Rovai 没有响应。」并提供「重试」。
读取成功或切换工作区时清除该会话的提示和退避。停留期间的后续失败共享这一提示。
队员、置顶、通用偏好、外观与运行时读取静默重试一次，持续失败在相应页面呈现并保留已有数据。
界面语言继续由偏好读取提示持有，Web 网络恢复继续按[断线恢复合同](../host-web-connection-recovery.md)核对原请求。
