# 队员身份与图像

## 队员身份与图像

`AgentProfile.id`、`Skill.id` 与 MCP `serverId` 各自在现有组件中稳定映射
`--identity-1..8`。稳定 ID 决定序号，主题只提供对应可读色值。身份色只进入头像环、名称或小型
身份点，不表示运行、权限、审批、Presence、Lead、Capability 或选中状态。

一个受控 `avatarRef` 解析一份头像。所有队员展示使用圆形或圆角头像，不再提供独立半身照。
新受管资产为 schema 3：一个 PNG/GIF 文件及显示取景元数据，不为不同尺寸派生第二张图片。
GIF 保持动画；各 `MemberAvatar` 用同一取景区域显示原动画。旧 schema 1/2 继续读取原有 icon，
保持旧取景和动画，不改回原图居中。旧 source 文件保留，不做批量迁移或清理。

未知引用、缺文件、完整性失败或图片加载失败统一回退到名称首字母；不能显示破图、绝对路径或远程 URL。
身份资产不得进入命令、Diff、审批、审计、错误、恢复或页面背景。头像不是运行状态或权限判断的来源。
格式、限额、静态渠道导出及受管存储边界见 [Member Avatar v1](../../contracts/member-avatar-v1.md)
与[成员投影不变量](../../architecture/foundational-invariants.md#member-projection)。

队员页的当前局部结构见
[`member-workspace` surface brief](../surfaces/member-workspace.md)；
会话内锚定身份卡见[结构化 Mention](structured-mentions.md#锚定人物信息卡)。

进入队员页时先显示现有名册，再异步读取 `members.list`；已打开队员页收到 Core 的
`members.invalidated` 后也异步读取。读取期间保留旧名册与当前选择，失败仍保留旧内容；在途读取之后
到达的新失效提示必须触发后续读取，旧结果不能覆盖较新的名册。事件只提示重读，不直接修改行数据，
也不要求同时重读 Runtime Installation。

## 队员配置页

右侧连续呈现“身份信息”和“运行配置”，不增加配置向导或跨区域保存。顶部用紧凑头像、名称、
团队角色与 Presence 对齐，不再重复智能体名称或快捷入口；名册的智能体图标仍可滚动并聚焦运行配置。
身份信息保留名称、团队角色和专业职责。性格底色、工作准则、成长课题合入默认收起的“更多设定”，
有内容时轻量显示“已设置”，空白不显示补全计数。折叠不改变生效或提交，校验错误自动展开并聚焦；
未确认的有效性格标签随一次保存提交，失败保留输入。

两部分分别通过“保存队员信息”和“保存运行配置”提交；当前主题的主操作 Token 用于保存和裁切滑杆。
成功更新对应保存基线并清除未保存提示，不清空另一部分草稿。外部冲突保留输入并阻止对应部分覆盖，
重新读取只放弃该部分修改。离页保护所有队员草稿。新增沿用同一表单，只填名称即可创建；
头像和更多设定可选，未配置 Runtime 明确保持未配置，不改变创建后的现有导航。

“更换头像”直接打开 Dialog，不在页面内展开选择区。上传是默认焦点和唯一主要操作；四个内置预设
默认收起在“使用预设头像”内，每次重新打开仍收起。移除位于左下方且只在有头像时显示，取消在右下方。
不常驻格式小字或问号；格式过滤、悬浮说明与失败提示承载必要信息。
选 PNG/JPEG/GIF 后同一 Dialog 切换为“裁切头像”，居中填满方形区域；可拖动、缩放、方向键微调和重置，
不显示多尺寸预览，不提供另一个常驻调整入口。取景只更新元数据；拖动和缩放不重建 Blob URL。
“确认头像”物化受管单文件并形成 Profile 草稿，主保存才提交引用。返回回到选图区；取消、关闭或 Escape
丢弃未确认选图，保留原头像、已确认草稿和文字草稿，焦点回到实际触发器。处理中关闭后晚到结果不得应用。
读图或保存资产失败明确反馈，更换未应用；文字仍可保存，不留下待完成裁切状态。

创建命令可携带头像引用；已有队员文字和头像继续使用独立命令，后一步用前一步回执版本。
文字成功而头像失败时明确显示部分结果，保留头像草稿，只重试失败部分；不声称跨命令原子性。
当前用户个人资料编辑不是队员编辑，保留其共享裁切、预览和静态图片处理路径。

智能体类型菜单展示现有产品图标，模型、推理强度和权限菜单共用中性选中底色、行高、勾选标记与浮层样式。
正常配置的队员信息、名册入口和运行配置区不附加“可用／可尝试运行”或验证机制说明，tooltip 与可访问名称
遵守同一规则。保留智能体名称、配置区已知版本，以及未配置、检查中和异常时的必要反馈与处理入口。
模型选项区分 Runtime 显示名称与选择 ID；有原生描述时展示，并可悬浮读取全文，不推断型号系列或版本标签。
模型菜单顶部只保留搜索框，按模型名称或 ID 在当前目录中本地筛选；不显示目录标题、刷新按钮或“最新”提示。
搜索框同时接受模型 ID：去掉首尾空白后，非空且不含控制字符的输入与原生目录 ID、当前手动 ID 均不完全相同时，
在结果列表内提供“使用 {ID}”（`Use {ID}`）选项，点击或 Enter 选择；不另设常驻入口、弹窗或模型管理列表。
目录始终来自原生智能体，不叠加队员环境。手动选择只保存为当前显式模型，初始 `options` 为空；不向目录或历史列表写入。
当前目录外 ID 作为普通已选行展示，重选不修改草稿；切换其他模型后旧手动行消失。保存、放弃和并发保护沿用运行配置表单，
模型是否可用仍由各 Adapter 的原生启动/会话机制判断，不因手动输入绕过原有运行校验。
模型策略的“默认”与推理强度的“跟随模型默认值”分别固定在各自菜单底部，不随结果滚动或搜索过滤。
搜索支持中文输入法、方向键选择、Enter 确认、Escape 返回触发器和 Tab 继续表单；清空或关闭搜索不会修改草稿。
空目录、搜索无结果与刷新失败仍可选择默认；已有目录在刷新失败时保留，失败说明与重试只出现在下拉框内部，不改变页面表单布局。

文件系统访问、审批、权限模式等字段继续服从原 Runtime schema、原始选项和默认值；可用性、模型缓存和
平台冻结状态仍来自 Core。视觉排序不改变初始选择：默认模型不写入显式模型 ID，选择固定模型也不自动填入
推理强度；选择“跟随模型默认值”删除对应 override。

权限推荐采用展开后呈现：关闭的下拉框只显示当前值，打开后在 Core `memberRuntimeDefaults` 对应的有效原生选项
旁以无底色、无边框的普通小字显示“推荐”，菜单底部保留“建议使用最高权限，体验更顺畅。”。推荐文字与原有
选中勾选独立，不调整选项次序或用户配置；默认值不在当前原生目录时不显示推荐。权限开关下方只保留
“建议开启，体验更顺畅。”，不增加角标或弹窗。Copilot、Kiro、Antigravity 共用的开关外框高度与最小高度均为
36px，与相邻下拉框对齐。英文对应为 `Recommended`、`For a smoother experience, use full permissions.` 和
`Enable for a smoother experience.`；开关状态为 `On / Off`，Antigravity 使用 `Auto-approve permission requests`
以保持窄窗口对齐。英文推荐菜单最小宽度为 360px，仍服从现有视口宽度上限。语言切换保留当前选项和未保存草稿。

同一 Runtime 内从显式模型切换到另一显式模型时保留用户已设置的参数，不按目录过滤覆盖值，
也不复制目录默认值。重选当前模型不修改草稿；切到 Runtime Default 清除覆盖值，再选显式模型不恢复旧值。

Pi 的可调模型显示“思考强度”与“跟随 Pi 原生设置”；无覆盖且已知只有 off/空档位或能力未知时隐藏字段。
清除只删除 override，不重置 Session 原生值。Pi 目录按独立观察身份展示，不受旧健康失败限制；切模不发起逐模型探测。

目录缓存状态沿用 Core 投影，Renderer 不自行计算 TTL。同一环境和身份的过期目录仍可用于选择。
读取失败显示“模型与参数尚未核对”，保留当前模型、参数与有效缓存；未枚举的已存值显示“尚未核对 · 值”，
允许更改或清除，不显示“不支持”或“当前目录未提供”。异步目录刷新只更新候选项，不改写草稿。
保存不以目录为门槛，执行交给原生 Runtime 判定，见 [Runtime Launch v74](../../contracts/runtime-launch-and-verification-v74.md)。

DeepSeek Harness 的两个权限字段以原生名称作为主标签：`sandbox_mode` 与 `approval_policy`。选项也逐字显示
`read-only | workspace-write | danger-full-access` 和 `ask | never`；中文解释只放在同一选项的次级说明中。
触发器、菜单、持久化值与最终 Host 配置使用同一个原生 value，不重命名为“安全模式”“自动模式”或其他
Rovai 概念。该表单由 Desktop 与 Mobile 共用；版本不兼容也复用同一状态投影，并明确显示最低版本
`0.1.5-rc.2`，不建立移动端专属文案分支。

### 队员环境变量

运行设置在模型和权限下方提供紧凑折叠的“环境变量 / Environment Variables”入口，使用 JSON 对象编辑。
通用和队员配置为空时，placeholder 展示 `{ "VARIABLE_NAME": "value" }`，示例不写入草稿或保存值；初始高度 104px，随内容增长，
上限为 360px 或视口高度的 45%。点击无边框高亮或阴影；移动端字号为 16px。
沿用表单保存、放弃更改和离页草稿保护，不提供检查连接。
所有值直接显示，删除隐藏状态、显示密钥入口及 `<saved>` 保留标记；不增加逐项添加变量入口或地址与凭据配对确认。
不添加常驻编辑说明；输入及失焦保持原始草稿，失败也保留草稿，
预览和提交使用同一字符串结果，成功后显示已保存的字符串形式。
不展示固定的环境生效说明或变量数量摘要。仅当当前 Runtime 有非空已保存通用配置时，展示“继承通用配置”、
“编辑通用配置”与“查看合并结果”；没有通用配置时保持原 JSON 编辑器。
查看合并结果在同一个文本框切换为可复制的只读内容，标题为“合并结果（只读）”，入口变为“编辑”。
返回编辑保留原队员草稿及格式；保存始终只提交队员变量及继承选择，不把预览复制成覆盖。
取消继承仍保留队员草稿。
编辑通用配置进入对应的智能体启动设置，顶部显示“返回 {队员名} 的队员配置”。返回保留队员、未保存草稿、
展开状态、预览模式和滚动位置；直接从设置进入时保持原“智能体”返回。离开通用草稿沿用保存/放弃确认。

Thread 队员列表不提供“重置队员会话”入口或确认弹窗，Desktop 与 Mobile 一致。
队长、模型信息及移出当前会话仍使用既有操作；边界见 [Runtime Launch v61](../../contracts/runtime-launch-and-verification-v61.md)。
值归 Host 私有存储，不进入普通队员资料或“应用到其他队员”。精确行为见
[Runtime Launch v69](../../contracts/runtime-launch-and-verification-v69.md)。

### 应用运行配置到其他队员

运行配置保存行提供无底色、无边框的“应用到其他队员 →”次级文字入口；hover/键盘 focus 加深文字并显示下划线。
手机上左对齐独占一行，点击高度至少 44px。来源只使用打开弹窗时已经保存的 Runtime、模型策略、
显式模型参数和原生权限完整快照，不读取当前未保存表单；有运行配置草稿、冲突、保存中或平台冻结时禁用。
这是一次复制，之后各队员独立编辑，不建立持续同步关系，也不复制身份、Presence、启动路径或环境变量。

弹窗展示来源队员、配置和可展开的权限设置；默认只选择尚未配置的其他队员。已有配置需显式勾选，并显示
原配置到来源配置的变化及覆盖人数。源队员和已移除队员不在候选中；配置一致、运行配置有草稿、正在保存或
当前平台冻结的目标不可选择。身份草稿独立保留，不因应用运行配置丢失。超过八位候选提供姓名/角色搜索，
筛选不清空已选对象；语言切换保留选择、输入和执行结果。

每位目标使用用户所见的版本，顺序调用原有 `members.runtime.set`；当前 Core 不以模型目录核对作为保存前置。
旧 Core 目录拒绝的兼容重试仍复用原逻辑。跨队员不声称原子提交，也不回滚已成功项。逐项呈现等待、保存中、成功、失败、冲突与结果未知：
明确失败只重试失败项；版本冲突先重新读取，展示最新配置后由用户再次应用。丢失回执必须先核对结果，当前
配置一致只报告“配置已一致”，不伪造成功回执；配置未应用且版本未变时允许按原版本重试，版本变化则重新选择。读取失败保留已有结果，
已确认写入之后的刷新失败不触发再次写入。保存/恢复在途阻止关闭和离开工作区；卸载后不继续启动余下写入。

Desktop 使用已有中性 AppDialog；Mobile 使用底部弹窗，可滚动内容与固定操作区，包含安全区留白。
共享中英文目录、主题、图标和头像；原生模型名称、参数值和用户资料不翻译。验证入口为
`pnpm test:member-runtime-apply`，与原有 `member-editor` 回归共同覆盖两部分草稿的独立性。

## 当前用户个人资料

队员管理名册顶部固定一个独立的个人资料入口；它不计入队员数量、过滤、排序、Presence 或 Runtime，
不提供移除操作。默认名称是“你”，默认圆形头像也是“你”字；自定义名称不会改变默认头像。
名称直接显示，不附加“· 你”；入口下方保留“个人资料”。折叠名册后保留头像和完整可访问名称。

右侧沿用现有详情页，以最大宽度 520px 的单列表单编辑头像与名称。名称支持清空恢复默认、32 字符计数和字段错误。
头像复用 PNG/JPEG 选择、尺寸/资源检查和现有可键盘操作的圆形取景器，支持恢复默认；当前用户资料
以 PNG data URL 存储，选择 GIF 时明确报错而不退化为静态帧。资料通过一个保存动作
原子提交；保存前的变化保留在编辑草稿中，失败保留草稿并提供重试。切换队员保留草稿，离开工作区沿用未保存更改保护。

保存成功后所有已加载和之后打开的历史对话作者栏、头像及结构化 Current User Mention 使用最新资料。
点击会话中的本人头像或结构化 Current User Mention 打开轻量资料卡，仅显示 160px 圆形头像和名称，
不显示“个人资料”标题、角色或运行状态。卡片沿用队员信息卡的锚定、键盘与关闭行为。
普通 Agent 正文中的 `@你` 保持不变。存储与上下文边界由
[Current User Profile v1](../../contracts/current-user-profile-v1.md)拥有。

分区保存、草稿保留、失败重试、冲突、新建、菜单键盘焦点、双主题与桌面尺寸。设置
`ROVAI_KEEP_MEMBER_EDITOR_FIXTURE=1` 可保留截图。图像处理和命令提交分别由现有头像测试与
`member-identity-save.test.ts` 覆盖；真实 App 验收仍遵循[开发隔离规则](../../development/local-workflow.md)。

模型菜单的搜索、输入法、默认语义及跨入口交互由 `pnpm test:runtime-model-picker` 的生产组件 Electron fixture 验证。

## 添加队员与名册排序

名册标题使用紧凑的“＋ 添加”与右侧下拉箭头，去掉整体边框和中间分隔线；各按钮独立提供 hover/键盘 focus 反馈，
手机点击高度至少 44px。主按钮进入对话添加，右侧菜单打开现有手动表单。移除旧名册选项和独立折叠按钮；
1px 分隔线的拖动、折叠/展开、双击/Home 复位及方向键行为保持。Desktop 拖动队员行，Mobile 从头像拖动；
不进入排序模式、不用手柄遮挡头像。拖动保留选择，同 Presence 组内换位，过滤外行保留；取消不提交，保存失败回退。
键盘焦点行支持 Alt+Up/Down，右键或菜单键可打开上移/下移操作。

AI 草稿复用普通会话所有结构，新会话按当前界面语言预填可编辑的添加请求，光标停在末尾；不自动发送。
切换语言、离开后返回及发送失败保留草稿，用户清空后不重新填入。空态保留三个起步操作：从喜欢的角色开始、按工作需要找搭档、设计原创伙伴。
快捷操作只填入正文，等待用户编辑和发送。没有换人控件、续建选择或预创建名牌。手机沿用既有折叠起步操作、
统一导航抽屉、列表/详情切换和 16px 输入；Return 换行。选择协助者、草稿边界与降级见
[Member Creation Flow v1](../../contracts/member-creation-flow-v1.md)。

`pnpm test:member-creation` 使用 production BusinessApp 与隔离 transport 验证选择、草稿切换、发送失败、

## 永久移除影响

永久移除继续要求精确名称确认。Core 预览列出会退出的会话、会变空的数量、队长交接和待释放任务。
只剩目标一人的会话不阻止删除；有未结束执行时明确展示原因，并提供“重新读取影响”。
失败保留输入和弹窗，重新读取发现名称变更时清空名称确认。历史身份与记录保留，当前语义见
[Camp Membership v3](../../contracts/camp-membership-v3.md)。
