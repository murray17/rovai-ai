# Automation 工作区

## 一级入口与构图

统一侧栏在队员之后、记忆之前提供“定时任务”一级入口。入口不依赖当前 Camp，进入前仍经过现有 Camp leave guard。
每次进入工作区首先显示全宽总览：标题与“新建”、全部/开启/关闭筛选、搜索、任务列表，以及三个模板入口。
读取到已有定义也不自动选择首项；空列表保留新建与模板，不同时铺开一个空编辑器。加载失败和没有匹配结果各有独立提示。

选择任务或开始创建后才进入列表与详情分栏。列表初始宽度取最小值 208px，筛选与新建操作贴近顶部，不预留空白标题行；
操作组在最小宽度下保持同一行。根据可用宽度为编辑器保留至少 320px；分隔条支持
拖动、左右方向键、Home 最小宽度、End 收起详情、Enter/双击恢复默认宽度。拖到最右侧收起详情，向左拖动可重新展开。
小于等于 820px 的窗口一次显示列表或编辑器，返回总览入口仍可用。列表与编辑内容各自滚动。

列表按 Core 顺序显示任务名称、计划摘要、启用图标、队员头像与独立操作菜单；沿 Core cursor 读取全部分页后再进行筛选
与搜索，搜索覆盖名称、Prompt 和计划摘要。选中项使用背景与 `aria-current`。总览模板区提示 App 运行且电脑唤醒时触发，
错过不补跑，不展示虚构任务。详情左栏的新建按钮展开空白与三个模板的创建方式选择。

## 创建与编辑

模板名称与计划对应 v30：Issue / PR 巡检（每天 09:00）、每周周报总结（周五 17:30）和新版更新说明（手动触发）。
模板只预填名称、Prompt 与计划，在同一新建草稿中切换模板保留队员、项目和通知选择。名称可留空，由 Core 从 Prompt 派生。

详情使用紧凑可编辑标题、Prompt、带头像/职责/运行时的队员选择、带路径的项目选择、运行时间参数和默认折叠的通知区域。
计划参数随六种类型切换；通知选择展示当前队员真实已发布 Bot，未发布渠道不能新增选中，已有选择仍允许取消。
新建页底部提供“创建”，Prompt 为空或没有可用队员时禁用。已有定义就地显示保存状态，无重复创建按钮。

已创建定义采用低频自动保存：用户输入后约 650ms 提交完整变化，就地显示等待保存、保存中、已保存、失败和版本冲突；
失败保留草稿并提供重试。立即运行、切换任务、新建、关闭、启用或删除之前必须先 flush 当前草稿，避免动作使用用户尚未
保存的旧配置。离开定时任务一级页面也复用同一保存流程：有修改时提交并等待成功后再切换，无修改时直接离开；保存失败
保留草稿和当前页面。版本冲突保留当前草稿，并让用户明确选择“重新载入”或“保留草稿并重试”，不静默覆盖。

删除使用同页两步确认。关闭只禁止未来领取，已运行项继续收口。一次性任务被消费后读取到关闭状态，界面不伪装成仍会
再次触发；“运行一次”仍可用，显式执行后定义继续保持关闭。

## 状态与结果

运行时间区显示 Core 返回的下次运行，详情下方展示执行历史。历史通过 `automations.runs.list` 每页读取 20 条，提供更早记录
入口；事件与低频刷新更新已展开的历史，不能只更新 `lastRun` 而让被新跳过记录遮住的活跃运行长期停留在旧状态。
核心标签为运行中、正在停止、运行成功、运行失败、已跳过；跳过原因在详情中区分
“错过触发时间”和“已有运行”。通知状态独立显示，因此成功运行可以呈现“运行成功 · 通知失败”。

历史行有真实 `campId` 时可打开执行对话，复用 App 的既有 Camp activation，不建立 Automation 专用阅读器。
运行中与失败记录也能查看执行过程；此入口不宣称存在成功结果。没有 Camp 的 skipped/派发失败行禁用打开动作。
成功结果仍只认 Core 冻结的 `resultMessageId`，通知失败不改变运行结果。

## 可访问性与主题

所有表单控件有持久 label，计划参数仅在对应类型下出现；通知组合使用 fieldset/legend。任务行、模板和操作均可键盘触发，
焦点遵循全局可见 focus ring。状态不能只依靠颜色；Day/Night 只使用现有语义 token，不增加主题专属业务结构。
